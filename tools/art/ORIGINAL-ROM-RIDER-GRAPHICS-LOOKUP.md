# ART-4K: exact original USA ROM rider presentation lookup

The exact 2,097,152-byte original USA ROM, SHA-256 `859ec99fdc25dd9b239d9085bf656e4f49c93a32faa5bb248da83efd68ebd478`, was independently checked against the imported 65816 bank82/bank83 disassembly. LoROM mapping matched 23,815/23,816 disassembly instruction-byte records; the one anomaly is at 82:9F02, outside the checked rider routines, where the imported listing's bytes are misaligned. The tool `tools/art/audit_original_rom_rider_graphics_lookup.py` independently verifies **27 byte-exact instruction fragments directly from the ROM** and examines the rider presentation pointer table. It uses original ROM data from the existing repository, no separate emulator or new source capture.

## Verified source architecture

- 83:ED33 calls the angle/presentation update. At 83:EE53 the program advances WRAM $0F83 with a delta, explicitly wrapping it into 0–23; 83:EE6F writes the 24-state value. Several speed, direction, state and track-relative branches precede the resulting presentation choice. This is a **24-state animation variable**; a 15° per step physical wheel rotation has **not** been proved.
- 83:EF10–F089 computes/clamps orientation and stores a six-bit value in WRAM $0F77. At 83:EED9 the ordinary branch applies **six successive ASL instructions** (multiplication by 64) to $0F83, then 83:EEE6 adds $0F77. Consequently the ordinary presentation index is **`64*phase + orientation`**, a **bijection over 24×64 = 1,536 combinations and the range 0..1,535**, before conditional stunt/overlay/state overrides. Earlier notes claiming five shifts and only 800 distinct indices were wrong and must not be reused.
- 83:EF0C stores the selected graphics ID in $0F97. 83:F0D7 copies the two rider graphics IDs $0FE9/$0FEB to a common graphics-work queue, with overlay IDs $0D3F/$0D41 handled separately.
- 83:F296 multiplies a presentation ID by **three**, indexes original ROM bank $20 from $8000, reads the two-byte source address and adds $23 to the one-byte source graphics bank offset. This is ROM lookup addressing, **not pose-angle inference**. The entire 1,536-entry ordinary index range occupies the three-byte table **$20:8000–$20:91FF**, inclusive; every table entry is sampled in the ROM auditor, and selected genuine source pointers are included in its machine-readable result.
- 83:F21A/F227/F26B write the source address, source bank and VRAM destination into DMA-list arrays, and 83:F290 sets the pending flag $0306. Original NMI code 82:B8AB/B8B7 reads and clears the pending flag. The NMI sets DMA channel zero for $2118 VRAM data transfers, a **32-byte 4bpp tile at a time** (82:B8D5, 82:B902). Static ROM bytes for these instructions are independently checked.
- Actual no-frame-skip original Mesen source sprites in merged #3103 and source-only PR #3104 independently show **23/23 changes** in the 64×64 racers' VRAM tile payloads under constant OAM tile numbers/palette IDs across ticks 1601–1624. Those PPU observations and the ROM instruction stream are different proof classes; **the exact writer PC, selected presentation indices and buffer lifetime at those captured ticks have not yet been dynamically traced**.

## Model-facing result

The provisional five-parent 2026 GLB, viewer, camera and material-ID render controls remain exploratory (#2832/#3101). A 24-state selector and a six-bit orientation suggest a useful **discrete source-index interface** for the rig, but neither the original 3D wheel angle nor physical pose follows uniquely from the selector. A temporary original sprite can map many 3D configurations to one 2D image through quantisation, palette redraw or artist-authored data. Avoid treating original-ROM indices as an automatically calibrated 3D rotation of 360°/24 or 360°/64, and keep the red completed-screen reflection separate from the OAM-local source orientation.

**Next cheapest decision:** instrument the existing original Mesen bridge for the fixed **$0306 queue pending**, the two graphics IDs **$0FE9/$0FEB**, selected **$0F83/$0F77/$0F97**, and the NMI DMA queue source and VRAM destination for the two **already observed upper-sprite events** (blue 1602→1603, red 1605→1606). Cross-check against the preserved original 24-tick PPU archive. Only launch a bounded new source emulator trace if current artifacts cannot answer the writer question, and freeze probe addresses and expected output first. A writer trace still would not identify a historical 3D mesh without independent spatial/pose evidence.
