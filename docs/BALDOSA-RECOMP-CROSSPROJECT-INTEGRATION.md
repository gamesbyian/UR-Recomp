## What is actionable now

**Independent decomp/RAM map.** `decomp/symbols.txt`, `decomp/ram.txt`, `decomp/subsystems.txt`, `decomp/hw.asm` and code hints give independently authored function/RAM names for the *same* USA ROM (SHA-256 `859ec99fdc25dd9b239d9085bf656e4f49c93a32faa5bb248da83efd68ebd478`). The upstream author reports 674 named functions and 620 RAM variables; these counts are upstream claims, not a local coverage acceptance. Consult using `python3 tools/query_baldosa_symbols.py --address 818050` or `--match 'finish|lap|stunt'`. Treat names and comments as external hypotheses until ROM/trace-confirmed. Do not mass-promote them into our canonical `docs/SYMBOLS.md`. Run `python3 tools/build_baldosa_symbol_crosswalk.py --differences` for locally/external differently named addresses, or `--out analysis/generated/baldosa-symbol-crosswalk.json` for all address-matched and unmatched entries, with CPU LoROM mirror normalization. This is a derived report, not a replacement canonical map.

**Nine original input routes.** Upstream routes target attract, 1P Race, Zoom Zoo Circuit, 2P, split-screen, VS, League, Define and Records. Original scripts are *not drop-in* UR-Recomp fixtures: they use Ema's runner grammar (notably `until16`) and his framework's timing model. `tests/input/qa01-baldosa-zoo-candidate.script` is a separately authored, non-gating attempt using our pre-existing UI entry sequence plus the drive sequence from `zoomzoo_1p.txt`. It should be tested in actual pinned original Snes9x and stock native builds; record guest-relative race entry, course identity, checkpoint/lap deltas, end condition and settled result before calling it a completion. Never count a route reaching the frontend as a player win. Our ledger currently remains **0/45 complete USA original/native event pairs** until retained evidence proves otherwise.

**OAM/HDMA candidate fix (high priority).** Upstream framework commit `075fbe4c` adds `g_hdma_oamdata_at_10c` and primes the PPU OAM address before HDMA writes to `$2104`; Ema's `src/main.c` enables the opt-in. Their commit `10b864b9` reports correcting split-screen sprites 96–99, with OAM checkpoints matching patched snesref. Our `tools/decode_uniracers_oam_split.py`, `tools/compare_active_oam_models.py` and active QA-08 P1/P2 sprite acceptance already investigate the `0x218` high-table target. **Do not replace our pinned snesrecomp submodule, inject a guest-visible fallback, or claim a confirmed defect from this report alone.** First compare their `dma.c` patch against our current DMA/PPU semantics and collect native/reference split-screen OAM snapshots at lines 0 and 112. If we reproduce the discrepancy, port only the bounded opt-in change, preserve existing stock and widened compositors, and run multi-mode acceptance.

**Cross-tier oracle limitations.** Ema's tools mask documented timing-phase WRAM bytes and stack (see `tools/state_mask.txt`); their route checkpoint comparisons include SRAM and optionally OAM. Masked checkpoint equality is useful for broad execution checks but does not demonstrate exact per-frame causality, complete all-course parity or screen/HD fidelity. Prefer meaningful semantic event counters, authentic terminal results, and unmasked local witnesses at the disputed frame.

## Bounded execution queue, in priority order

1. **QA-01/QA-07:** replay upstream Zoom Zoo and Race inputs in the appropriate exact-USA original/native drivers. Check actual terminal event/result and measure how far route alignment extends; if one full original/native completion is obtained, promote to our existing 45-case census via its evidence/identity gate. Do not build a second generic runner.
2. **QA-08:** discriminate the OAM/HDMA fix in our pinned runtime at the exact 2P seam; only integrate code after a reproduced native/reference difference and targeted stock+Remastered regression. Coordinate with active graphics PR, do not overwrite it.
3. **ROM archaeology:** query upstream independently named `818050` (lap contact), `81C7E1` (countdown), `83E7A5` (finish), `80C775` (result recording), `80C8xx` (per-mode result), and annotate independently verified overlaps/disagreements only. Prioritize these over indiscriminate naming.
4. **Framework experiment, on its own branch:** test beam sync, native resume/interrupt handoff, `paced_bus` and historical variant roots individually against our pinned native/reference and CI speed. Never adopt all fork deltas by advancing the whole submodule: it is dozens of commits ahead and modifies broad PPU/CPU/core code.
5. **Deferred until Windows primary acceptance improves:** WebAssembly, browser lockstep/CRC, Raspberry Pi/ARM64, launcher integration, mod packaging and other platform ports. Their implementation is valuable evidence but should not displace our current completion/QA-02 recovery priorities.
