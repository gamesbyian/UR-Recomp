# Original author testimony: 16 pedal variants versus authenticated 24×64 ROM graphics

**Source evidence, not a recovered 1994 3D file.** Nintendo Life's [March 9 2010 historical interview](https://www.nintendolife.com/news/2010/03/feature_the_making_of_unirally) (originally printed in GamesTM) quotes original DMA Design developer **Robbie Graham** saying that the unicycle's production 3D geometry was highly detailed, that the SNES used pre-rendered 2D images of that asset, and that the unicycle could **tilt, stretch with speed, independently move its saddle**, and flip in stunts. He recollects **16 rendered pedal variants for most positions**. This is direct production testimony about the art pipeline and authoring behaviours, NOT an authentic original 3D file or an exact physical joint/angle mapping. Avoid guessing a screw thread pitch, speed-stretch curve, 16-step pedal phase angle or saddle motion law from the wording alone.

**Independent machine-code source observation:** Merged #3104/#3107 identify a genuine indexed **24 distinct graphics phases × 64 orientation indices = 1,536 ROM-defined packed 4bpp primary graphics states**, with 48/48 original live Mesen sprite matches. The source's ordinary 24-state modulo index is not independently identified as one artist-exported pedal rotation. The historical *16 pedal variants* and executable *24 presentation phases* can be simultaneously correct if the ROM's states encode a mixture of art variants, wheel frequency, interpolation or frame editing. There is no evidence yet for any specific 24→16 conversion. Do not relabel the ROM 24-index as 16 physical angles, or treat a difference as disproving the eyewitness.

## One fixed source-only period discrimination

New standard-library-only `tools/art/audit_original_rom_phase_periodicity.py` authenticates the **original SHA-256-pinned USA ROM**, reuses the existing *single* 1,536-frame exact packed-tile 4bpp renderer and scores **all 64 original orientation indices**. For every orientation, independently define the *pre-existing* source phase-varying 4bpp pixel support across the complete 24 source phases. Compare the **same eight source base phases 0..7** against their nonwrapped offset phases for **each lag 1..16**, with identical pair count for every lag (8×64=512). Within phase-varying source pixels, report exact 4bpp index fraction, source-opaque exact-index recall, alpha TP/FP/FN and alpha IoU for each lag. Lags 1..15 are explicit source-space null controls: a striking lag16 repeat would be *compatible* with an artist sixteen-pose cycle, not proof that the ROM's 24-state transition is a fixed 22.5-degree wheel step. A poor lag16 result does not refute the eyewitness about pre-rendered authoring variants, since phase 24 may sample a different stage of the content pipeline.

No new emulator, CI workflow, continuous wheel-parameter tuning, extra rig, copied copyrighted original sprite, or new art is needed. The real ROM is already available to normal project tests; the synthetic test demonstrates that a genuine 16-repeat is detectable and fake/empty/non-4bpp sources fail closed. That actual original-ROM test **has already passed** in merged #3135: lag16's exact 4bpp index match was **42,644/59,992 = .71082811** against the strongest other tested lag8's **42,754/59,992 = .71266169** (110 extra index matches for lag8). The 16 offset is not a distinctive period in the native 24-phase original table under these fixed comparisons. The artist's historical 16 rendered pedal variants remain a separate original production-stage fact, not disproven or converted into physical 1994 degrees. All original source views are previously inspected, so this is **retrospective diagnostics**, not a blind test.
