## Procedure for each reconnaissance pass

1. **Refresh source identities** via public GitHub API or a clean clone: default branch SHA, full tree SHA, commits since last examined head, all branches and tags, releases/assets, open/closed PRs, issues/discussions if enabled, fork network if useful, submodule pointers, licenses, changelog, CI jobs, build docs and upstream open task registry. Check pagination, errors, truncation and rate limits. Do not conflate `updated_at` with a source push; compare both HEAD and PR/issue changes.
2. **Inventory by domain, not by headline.** Read changed source, tests, workflows, docs/research, tasks and generated map files. Both full trees must be traversable by pinned SHA. For Baldosa inspect `recomp/`, `decomp/`, `src/gen/`, `src/game_rtl.c`, `src/main.c`, `src/web_*.c`, `web/`, `tools/`, `tests/routes/`, `framework_pins.txt`, submodules and release workflows. For Malmazuke inspect `src/core/`, `src/app/`, `tools/unirally_lab/`, `tests/`, `docs/research/`, `docs/map/`, `docs/decisions/`, `tasks/`, locks, workflow and independent review records. Enumerating a path is **not** understanding its behavior; track which changed files and claims still lack semantic review.
3. **Classify each changed behavior and usable technique** into `already implemented`, `external corroboration`, `candidate read-only experiment`, `candidate compatible module`, `contradicted`, `deferred until a live blocker` or `not relevant`. Reference `docs/CROSS-PROJECT-BEHAVIOR-CORROBORATION.md`, `docs/RESEARCH-LEDGER.md`, `docs/SYMBOLS.md`, the 35-row apparatus matrix and `analysis/three-project-reuse-opportunities.json` first. Compare UR source and open PRs, not October status notes; do not raise duplicate jobs for already merged work.
4. **Qualify one cheapest useful discriminator per genuine live blocker.** Specify upstream SHA/file/line or PR, claimed behavior and evidence class, PAL/USA opcode/data homolog, correct ROM and reference core, candidate executable/source hash, exact pads/frame origin, earliest divergence, downstream consumer, adversarial negative and reviewer. Use `tools/query_upstream_knowledge.py` and `tools/select_three_project_reuse.py` rather than adding competing tools. The PAL 50 Hz runner cannot award USA 60 Hz game truth; upstream success cannot award physical Windows or QA release credit.
5. **Hand findings to the existing owner.** Update the current source catalog/worklist only for genuinely new leads; refine the existing subsystem's test/handoff, with actual-byte fingerprinting and required third-party manifest for imports. Add a succinct PR/issue comment or a small, independently reviewed PR where action is warranted. Resolve each investigated lead with disposition, reason, next trigger, exact source pin and whether it changed any current release criterion (normally `none`).
6. **Close the weekly pass.** Refresh the provenance inventory only after checking it; summarize changed heads, PR/issue deltas, technical discoveries, prevented duplicates, remaining unclassified file families, one next reproducible action and explicit stop condition. Mark the board item `hold` once the initial review is covered and only the weekly/change-triggered watch remains; restore `ready` when an actionable new upstream change or real blocker appears.

## Proof, rights and stop rules

- **No semantic authority from headlines, generated maps or source agreement alone.** Require original USA verification and independent review for any game truth or release claim. Coverage percentages and PAL CPU/PPU/HDMA addresses are scoped to their reported ROM, code domain and observation corpus.
- **No double implementation.** One guest simulation, Modern frontend, source/QA evidence system, symbol index, release ledger, existing agent work pool. Do not import Malmazuke's PAL native engine or Baldosa's old host/web UI as a parallel product.
- **Licenses remain distinct.** Baldosa's root code is PolyForm Noncommercial 1.0.0 with separately licensed framework; Malmazuke's project-owned code is MIT. External game assets, extracted content, ROMs, captures and transitive tool dependencies require their own rights review. Read-only descriptions are not source imports.
- **Evidence is not all committed upstream.** Malmazuke describes many original-capture recipes under gitignored `local/evidence/`. Recreate source-qualified outcomes only where technically necessary and permitted; a PR saying 919 runs passed is not an independently inspected 919-run corpus in UR.
- **Stop without creating work** when an unchanged HEAD, already-integrated upstream mechanism, unsupported PAL-to-USA projection, held physical tester or superseded CI is the only rationale. A weekly no-change check is sufficient, not an hourly PR.
- All actual test receipts must identify source/ROM/reference/candidate and exact invoked commands; `docs/RELEASE-QUALITY-LEDGER.json` alone controls acceptance.
