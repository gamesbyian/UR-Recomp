## Significance classes

Ordered by decision value. A finding is triaged in this order, whatever computation produced it.

| Class | Meaning | Admission rule enforced by the validator |
| --- | --- | --- |
| `original_native_discrepancy` | Original and native differ under the same race-relative input | Needs original **and** native evidence and a declared race-relative lag |
| `source_backed_behaviour` | A state transition or behaviour confirmed by the original or by recovered source | — |
| `untested_circumstance` | A gameplay circumstance no oracle has exercised | — |
| `graphics_observation_gap` | A PPU/visibility fact current observers cannot see | — |
| `windows_durability` | A Windows durability or recovery defect, or a bound on one | — |
| `reproducible_anomaly` | Reproducible but unexplained | — |
| `method_hazard` | An experimental design error that would mislead a consumer | — |
| `fingerprint_novelty` | Native fingerprint novelty with no shown consequence | Can never be an open assignment or have an owner |

Every finding names an exact reproducer command, its source artifacts (run IDs, executable/ROM digests, census tokens), the remaining uncertainty, the owning lane and **one** resolving experiment. A closed finding records its resolution; a handoff names the receiving implementation lane.

## Race-relative alignment is mandatory for original/native replay

The ordinary 2P route enters the race on different absolute host frames in different runtimes ([staircase](TWO-PLAYER-FIXTURE-PLAN.md): Beetle 1133, Snes9x 1134, generic native 1135). Feeding identical absolute-frame input to both and comparing the same host frame therefore compares different race ticks, and the `82:A5F3` scheduler-parity gate turns that into real kinematic differences. The ordinary 2P regression already corrects this with a measured +1 shift. **Any** new original/native replay must do the same, with a lag measured *before* evaluation and never searched per case (RF-002, RF-003).

## Lag-frame census: a common cause (RF-014, handed to QA-01)

`80:FAC9` waits for the next vblank on `$4212`. `80:FADF` then decrements direct-page `7E:00C6` modulo 32 and writes `table[$C6>>1]` (table at `80:FBAF`) to `7E:0BDE/0BFE`. Each decrement of `$C6` is therefore one completed pass of this wait continuation. Baldosa's imported RAM map names `$C6` `wCursorAnimTimer`, so it is **not** a global simulation-frame counter: "game frames" below means vblank-wait passes, and a host frame without one is a lag frame only where the wait runs every frame (QA-01 source preflight on #1537). Races, demos, scheduler pauses and counter restores are outside that reading. [`tools/qa_lag_frame_census.py`](../tools/qa_lag_frame_census.py) counts decrements between dense dumps on every engine for the same controller stream, with no instrumentation.

| Stock 2P route, host frames 2–1126 | Vblank-wait passes (`$C6` decrements) | Host frames without a pass |
| --- | ---: | ---: |
| Snes9x | 801 | 323 |
| Beetle-bsnes | 802 | 322 |
| Modern native (`4c1c8b56…`) | **773** | **351** |
| Generic SNESRecomp native (no Modern patches) | **772** | **352** |

The no-input attract cycle (host 2–4002, one counter-rewrite window excluded) shows the same pattern: native **1,311** passes, Snes9x 1,326, Beetle-bsnes 1,327. A frame without a pass is a lag frame only where the game runs the wait every frame (menus, loads); races and demos don't use it.

The two independent reference cores agree within one frame. Both native builds complete 28–30 fewer game frames, so the deficit is in the shared SNESRecomp runtime or generated code, not the Modern product host. Every one of the 27 differing windows is a screen transition or menu slide (raw `7E:009F` values `0x84`, `0xD7`, `0x3D`, `0x6D`, `0x91`); in steady menus all three run one game frame per host frame. At one-frame resolution the sharpest window is the load during which `7E:009F` changes `0x84→0xD7`: all engines hold `$C6` from host 426, the reference cores resume at 436–437 and reach `0xD7` at 440, native resumes at 442 and reaches `0xD7` at 446. Native needs about 5 extra host frames for the same load. The resulting `$C6` offset (4 mod 32) is frozen during the race and explains RF-012's `$0BDE/$0BFE` offset of 8 exactly. Native losing game frames at heavy transitions is the most economical common explanation for RF-012 (longer result phase), RF-013 (later, phase-dependent entry) and the 1P result-handoff seams QA-01 is chasing. It is a hypothesis to adjudicate, not a ruling. AGENTS forbids tuning `$4212` merely to match one emulator; the question is why native spends extra host frames on the same guest work.

## Product core: register accesses saw later fetch clocks (RF-017, resolved 2026-10-15)

With RF-015 corrected, the Zoom Zoo follow-through still left the result screen one field early from result +2. **Snes9x and bsnes agree byte-for-byte** there (bsnes can now take the movie's anchored SRAM), so the native is the outlier. The compute between the two VBlank waits matches within 54 of 712,980 clocks. The cause is ordering inside Baldosa's generated blocks: `paced_bus` code charges a block's later fetches before its register accesses. Block `80:FAD6 LDA $4212 / BPL` therefore reads `$4212` 16 clocks late, crosses V=225, and leaves the wait before the NMI that the original takes inside `82:8035`, 556 clocks ahead. [`tools/baldosa_io_access_clock_order_patch.py`](../tools/baldosa_io_access_clock_order_patch.py) charges static clocks per instruction only in blocks with a static register access. Every block total is unchanged, and `--verify-gen` proves it on the regenerated `src/gen`.

The candidate gives Zoo `strict_candidate` with **all six source follow-through pairs equal** (base: +16 menu 188 vs 246). Bowl, Switcher, Dragster, all 18 2P seed × reference pairs and the attract census are identical to base. It is not yet in the Windows bridge; hosted re-execution (`qa01-event-campaign` `baldosa_io_clock_order`) and QA-01 adjudication come first. Full account: [RF-017 report](RF017-IO-ACCESS-CLOCK-ORDER-20261015.md).

## Product core: SPC rate, `[dp],Y` pointer reads and HDMA stall (RF-016/018/019, 2026-10-15)

Three more timing errors in the product core were attributed by trace and corrected in staged candidates on top of RF-015 + RF-017 ([report](RF016-019-TIMING-CORRECTIONS-20261015.md)):

- **RF-016:** the SPC700 ran 0.165% fast. The fix makes attract load 941–1098 exact, but it is not the cause of 2P seed 50048000 or Switcher +4664.
- **RF-018:** every `[dp],Y` access charged its pointer twice, so the attract decompressor ran 29% slow per access.
- **RF-019:** HDMA's per-line CPU stall was never charged, so the HDMA-heavy attract demo race ran about 4% fast.

With all three, the no-input attract run matches the references through all five loads and the demo race. The 18 2P pairs and four 1P cases are unchanged; no regressions. The one seed where both references agree and native differs is now RF-020, traced to an SPC timer-phase knife-edge: the first SPC reset at host ~4930 is honoured one driver tick (3,200 SPC cycles) sooner on native.

## Knife-edges: SPC timer phase and witness fragility (RF-020/021/022, 2026-10-16)

Dragster's one-frame-early terminal has the same root as 2P seed 50048000: the sound driver honours the post-race SPC reset only after a fresh timer tick, and native's timer phase relative to the CPU differs from both agreeing references. Native also starts the SPC only at the first port write (RF-021). Anchoring it at power-on makes the boot handshake exact. Adopted alone, though, it flips Zoom Zoo's follow-through and three attract loads while leaving the 2P set unchanged: current matches include knife-edges sensitive to ~100 SPC cycles (RF-022). Report: [RF-020/021/022](RF020-022-SPC-PHASE-KNIFE-EDGES-20261016.md).

## SPC frame clock and the power-on anchor (RF-023/024/025, 2026-10-16)

Two more APU-clock errors were found. The frame clock gave every host iteration at least one field of SPC time (RF-023), and the beam omits the NTSC short scanline (RF-024); together they let the SPC drift ahead of the CPU. With both corrected, the native SPC age tracks Snes9x within 2 cycles over 2,867 fields, and **2P seed 50048000 reaches exact agreement with both references** under either power-on anchor. With the empirical anchor 2,446 the candidate also turns Dragster into a paired candidate (+2081 = +2081) and keeps Zoom Zoo, Bowl and all five attract loads. Every witness where the references agree then matches, except Switcher. The anchor that reproduces the reference SPC age exactly (0) loses Zoom Zoo's follow-through, Dragster and three attract loads (RF-025): those agreements remain knife-edges, now traced to CPU/SPC handshake timing. Report: [RF-023/024/025](RF023-025-SPC-FRAME-CLOCK-20261016.md).

## SPC700 bus accesses on their hardware cycle (RF-026, 2026-10-16)

The native SPC700 executed each opcode on its first cycle, so its port and timer accesses ran 1–7 cycles early. Executing each opcode on its last cycle removes the power-on anchor dependence (RF-025 resolved). With the exact-age anchor, the full staged candidate (RF-015…019, RF-021 `--anchor 0`, RF-023/024, RF-026) matches **every witness where Snes9x and bsnes agree, except Switcher**: Zoom Zoo and Dragster with all follow-through and SRAM pairs, Bowl, all five attract loads, and 16 of 18 2P pairs, the other two being reference knife-edges. Report: [RF-026](RF026-SPC-BUS-CYCLE-20261016.md). Switcher is traced there as RF-027: native reaches the post-race `80:FAC9` wait 770 clocks early, built from a ~160-clock race-field residual carried into an NMI-disabled loader and widened by the driver-upload handshake.

## Interrupt-entry cost: every agreed witness matches (RF-028, 2026-10-16)

Baldosa charged nothing for the 65816 interrupt-entry sequence (62 master clocks on SlowROM), so NMI handlers started early against the beam. That offset, carried out of the last race field, was Switcher's root (RF-027, resolved). With it charged, the full staged candidate (RF-015…019, RF-021 `--anchor 0`, RF-023/024, RF-026, RF-028) matches **every witness on which Snes9x and bsnes agree**, with no tuned parameter:

- all four 1P cases are paired candidates with follow-through and SRAM equal;
- 16 of 18 2P pairs are exact, and the other two are Snes9x/bsnes disagreements;
- the attract census matches 5/5.

Hosted run 38879846733 reproduces the three campaign cases as paired candidates; QA-01 adjudication comes next. Report: [RF-028](RF028-INTERRUPT-ENTRY-COST-20261016.md).
