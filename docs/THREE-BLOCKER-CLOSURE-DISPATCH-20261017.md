Existing [QA #1806](QA02-ORIGINAL-GAME-ACTUAL-WINDOWS-NTFS-DISKFULL-20261017.md) **already** proves default raw SRAM allocation can refuse on truly full NTFS, exit 8, preserve old bytes, free the disk and reboot; it does **not** prove named-profile post-raw typed failure. Independent QA [#1810](https://github.com/gamesbyian/UR-Recomp/pull/1810) is the pending named-profile immutable-artifact verifier. Do not write a second transaction model or replace this store with SQLite.

**Exact red at snapshot:** [Windows bridge 39091080467](https://github.com/gamesbyian/UR-Recomp/actions/runs/39091080467), product head `9b861367a8286dbc1c51a21c0d23d77a6d3417b4`, failed step *Prove original packaged CMD save on actual full NTFS volume*. The helper currently checks `exc.winerror in (112,39)`; a true Python `errno.ENOSPC` may arrive without such a `winerror`. That is a **specific hypothesis for root cause**, not a proven allowed fix. On that head unit tests, hygiene and Modern execution seam passed. Debug the actual exception's type, `errno` and `winerror` at `write/fsync/close`; distinguish fill-loop exit from guest after-raw typed error. **Never** blanket-accept errno 28 as a valid post-raw witness. Require an independently executed second Windows process returning actual OS 112, full-volume `W:` confirmation, real original packaged guest progression into the intended saved-write window, typed checkpoint refusal, exact preserved raw/typed/selector/catalog before-and-after byte hashes and two new cold executable boots. Retain the failing source artifacts and mark setup failure as setup failure. Reject use of accidental exceptions on non-W: disks.

**Finite post-crash state and recovery contract (exact bytes, locks and generations in existing code):**

| Observed authenticated state | Permitted reaction |
| --- | --- |
| Old guest raw + old typed, abandoned authentic intent | Preserve old, retire only safe abandoned intent |

| New guest raw + new typed + same authorized intent | Recognize committed state and retire; **no duplicate awards/generation** |
| Unknown, corrupt, short, mismatched, symlinked, stale or unjournaled state | Fail closed, preserve all originals, require explicit R/T/S/Q or safely quit; healthy other profiles remain operable |

## C. Genuine original pixels: three causal defects, two distinct deliverables

**Existing qualified sources:** the 2014 original Snes9x authentic PPU archive, exact 263-frame 2P/finish source comparisons in [current grey-phase study](QA08-RESULT-GREY-PHASE-112-CYCLE-20261017.md), and merged 65 consecutive real moving 1P pixel-exact Windows source receipt [#1815](https://github.com/gamesbyian/UR-Recomp/pull/1815). Real UHD geometry and 7:6 viewport are protected by [#1779](https://github.com/gamesbyian/UR-Recomp/pull/1779). **65 exact 1P frames does not imply result or source CPU-equivalence.**

**Separate current branches and authority:** [#1780](https://github.com/gamesbyian/UR-Recomp/pull/1780) is the *clean* title-scoped first-line HDMA/V0-before-HDMA production slice; it remains HOLD because it is not a source-equivalent complete journey. [#1807](https://github.com/gamesbyian/UR-Recomp/pull/1807) is a **separately held experimental** five-bit brightness-*before*-color-math A/B, explicitly DO NOT MERGE; [#1813](https://github.com/gamesbyian/UR-Recomp/pull/1813) carries source-only 65-frame correspondence to reconcile with existing main receipts, not production rendering. Historical broad graphics #1641/#1649 are source archives, not automatic merge targets.

**Three different residual classes require different source discriminators:**
1. **Blackout / INIDISP** at guest4016: trace original/natively authored `$2100`/forced blank and precise beam/VBlank-to-PPU ingestion at the last equal and first wrong frame. Avoid global frame rephasing.
2. **Recurring grayscale pulses**: approximately 158,191 >1-step grayscale errors in 13 sampled pulses, aliasing at a 112-field sample pattern. Observe original/native CPU `$2121/$2122` CGRAM writes (values, V/H, origin), HDMA/raster replay and palette effective state at first mismatched scanline. The 112-field recurrence is a sampling alias, **not** a proven underlying palette period or permission for a +32 output shift.
3. **Medal-shaped chromatic residual**: stable mask **296 positions**, of which **287 exceed one RGB5 level**, recurring across 25 frames in three bands (y91..105/115..129/139..153). At two or three original-source registered pixels record actual winning OBJ tile/index/priority, BG/main/sub/fixed-colour operands, CGRAM entry and order, and original native OAM DMA contents at **the same guest source epoch**. A nearby OAM slot in old `c782...` evidence is not a proven winner in current RF-017 `b735...`.

**Do not build an entire second SNES renderer or offline screenshot system:** extend the existing read-only `tools/qa08_result_grey_phase_archive_check.py`, current source-capture probes and source pinned real Windows A/B. One compact per-pixel provenance trace, supported by exact source original, is better than more all-frame captures. Guard against invalid file-channel/BGRX→RGB5 mapping, frame offset, tolerance and masked-pixel shortcuts. For each attempted correction provide a non-regression matrix of already exact 1P/2P pixels, countdown, result, blackout, complete guest CRC, source PE, original ZIP and final ROM-free Windows package.
 
**Two deliverables:** (A) a small **clean** production source/PPU correction based on #1780 plus any separately proven follow-up, independently recompiled and validated; (B) HD racer likeness, separate from PPU correctness, following [HD reconstruction brief](HD-RACER-CHARACTER-RECONSTRUCTION.md) and [projected landmarks](HD-RACER-PROJECTED-LANDMARKS.md). Render one coherent reference-grounded unicycle rig across multiple poses, assess stock silhouette, tire/saddle/fork/pedals and original motion at gameplay size, and obtain **new explicit human visual approval**. Prior procedural 4× art remains vetoed, regardless of pose hashes.

**Method transfer:** Dolphin's [FIFO replay facility](https://github.com/dolphin-emu/dolphin) shows how recording graphics operations helps diagnose later pixels, but its GameCube FIFO is **not** a SNES PPU interface. Adapt the *event → effective raster → pixel winner* separation to existing SNES register/OAM/CGRAM journals. [Mesen2's SNES PPU debugging tools](https://github.com/SourMesen/Mesen2/blob/master/Core/SNES/Debugger/SnesPpuTools.cpp) are a useful inspector design reference, **not a replacement for our pinned original oracle**. [bsnes fast-vs-accurate PPU test issue](https://github.com/bsnes-emu/bsnes/issues/180) illustrates why passing a faster raster path does not establish underlying hardware accuracy. Cross-emulator agreements are supporting witnesses, not identical independent hardware tests.
