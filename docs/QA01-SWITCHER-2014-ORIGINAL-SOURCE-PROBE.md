# QA-01: finite original 2014 source eligibility for Switcher Race B

This work runs the **archived original 2014 SNES movie in pinned original Snes9x**, without building or invoking Baldosa. The actual 2014 source is already proven to finish the first Crawler Race (Dragster), Circuit (Zoom Zoo), and 45-second scored Stunt (Bowl). It does **not** follow automatically that a genuine Switcher Race B result appears in an independently selected bounded movie window.

`tools/probe_original_switcher_source_2014.py` reuses the existing original movie/RNC/SRAM/original event detector, the canonical stream 4 (track ID 3), and the source-only settled Race result `0x99` rule. The 22,000-original-frame horizon is explicit. When an observed, stable source result and new sustained active course entry are present, retain the original entry frame, exact course identity, result onset and original course-entry snapshot. If the source does not establish this pair within the horizon, record **not qualified within horizon** with the original diagnostic, not a conclusion that the game cannot complete Switcher, nor a license to synthesize game input or infer a native fault.

The narrow workflow `.github/workflows/qa01-switcher-original-2014.yml` builds *only* the original reference core, unlike the separate full original/native scored Bowl experiment in #1119. It uses the pinned Baldosa project's existing Snes9x runner, not a new emulator or gameplay backend. No guest memory writes or controller shifts are allowed.

**Admission rule:** This result is original-only evidence, not native Switcher progress. Regardless of a green check or qualified original source, **USA completed course acceptance remains 0/45**. If a qualifying Switcher original result emerges, separately calibrate a fresh stock Switcher entry under original and Baldosa and compare contact/checkpoint/finish/result and PPU times before entering the release ledger.

## Original source diagnostic window correction

The shared source diagnostic previously used **Bowl frame 11985** as a fixed end point for the foreign-course raw-frame count, and stopped the foreign-course *run* detector at the earliest observed result menu of the desired type **regardless of course identity**. This is particularly misleading for Switcher (USA Race B, track ID **3**): the same archived movie already has an earlier Dragster `0x99` Race result, and Switcher's meaningful post-11985 source region could have been silently excluded from the returned diagnostic.

The diagnostic now anchors to the **first actually observed sustained candidate course's active frame**, stops only at a **later source result of both matching menu and the desired course track**, or at the exact finite trace end if no target result exists. Both foreign-course counters use that **same end-exclusive window**, published as `source_intervening_foreign_active_window` alongside a zero release-credit flag. This changes **diagnostic reporting only**; the existing independent `source_event()` qualification and original/Baldosa guest execution are untouched. Synthetic tests include an earlier different-course `0x99` result and a later sustained foreign active interval beyond frame 11985, plus no target result. They do **not** prove that archival Switcher driving qualifies in the 48k/96k original scan.

## Original-execution horizon attestation (2026-10-10)

A further hardening of the **existing original-only witness** requires an independently observed Snes9x script `dump source-horizon` at the **requested** host frame, with a complete local 131,072-byte original WRAM snapshot. The original scan script is now `wait N; dump source-horizon; quit`. Neither an exit code of zero nor the final changed-byte trace index is sufficient proof of an N-frame execution: a working original emulator could have no *changed* watched bytes at its tail. The actual dump confirms the full requested host boundary, and the zero-credit `source-event-diagnostic.json` now includes `original_source_horizon_host_frame`, `original_source_horizon_wram_bytes`, and `original_source_horizon_observed_from_guest_dump`.

Both **negative** original source verdicts and any **qualified** source result now require that horizon attestation. A missing/duplicate dump marker, a premature source exit, a wrong host frame, or an incomplete horizon WRAM capture aborts source qualification. The dump remains in the ephemeral workflow workspace and **is not uploaded**: the durable report retains the boolean, length and actual host frame only. The pre-existing 22,000-frame negative witness predates this extension and is unchanged; it cannot be retrospectively claimed to have carried this new end-marker. This patch neither performs nor claims to perform the manual 48k/96k scan, changes original controller masks, or provides native Baldosa parity. Official full-event release credit remains **0/45**.

The [original-only 48k Snes9x run **38053986565**](https://github.com/gamesbyian/UR-Recomp/actions/runs/38053986565), artifact **11670742951** (ZIP SHA-256 `ee3a3a4748b751bb20a8f18f2ab80257b910fb21e41b3d146423f0d88afee37e`), has established **actual** Switcher (course 04, track ID 3) source gameplay and a stable Race B result. The machine-readable compact original report is retained at [`analysis/data/switcher-original-2014-observed-race-b-result-48000.json`](../analysis/data/switcher-original-2014-observed-race-b-result-48000.json), with no ROM, movie controller bytes, SRAM or raw guest memory.

Observed **first sustained original Switcher entry** is frame **12,327**; original source Switcher active total **4,668 frames**, with final active frame **17,028**. Source DP `7E:00CE` reports track **0** for **34 active frames 16,991–17,024**, then returns to track 3 for the four active frames **17,025–17,028**; at **17,029** the game leaves active play, and the **stable original Race B result** `7E:009F=0x99`, `7E:0313=0`, `7E:00CE=3` appears **17,030–17,087**. A later unrelated course-0 Race result appears at frame 25,344. The entire actual source scan was successful, **but the old generic course-identity guard rejected this first event** due to the authentic 34-frame ID=0 stretch. It would be false to summarize this as “there is no Switcher result in the source”.

The original-only classifier now admits precisely this **Switcher Race B terminal prelude form** while continuing to reject any other sustained foreign active course or scene. Requirements include course ID 3; original result menu `0x99` with exited guest race flag for eight frames; exactly **34** consecutive active track-0 frames beginning 39 frames before result onset; a correctly active track-3 frame preceding the transient; four active track-3 frames immediately after it; and exited active gameplay before stable result. Missing return, earlier unrelated course, wrong course ID, malformed result or shifted prelude must be rejected. The general foreign-active-course rule remains unchanged for Zoom Zoo and all other courses. The returned `original_only_transient_handoff` label makes the exception visible; **it is not gameplay physics attribution or permission to move input frames**.

This is a strict **original-source eligibility hypothesis awaiting a fresh source replay and original-source result-text inspection**. It is NOT a native Race B parity pass, independent result time, guaranteed positive P1 outcome, or authorization to advance any USA release gate. Use this positive source as the candidate for the existing original/native full-event runner **only after new original entry capture and PPU result evidence**, then compare actual guest-relative terminal timing, P1 finish/time, P2 state and exact PPU text. **USA accepted 0/45**.
