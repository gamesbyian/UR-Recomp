## Initial independent comparison: findings requiring adjudication

1. **X-boundary mismatch, unresolved:** upstream `WsSrcCell` normalizes `tx %= s_src_cols` and wraps negative X; UR `ur_ws_course_tile` refuses `cell_x < 0 || cell_x >= coarse_w*4` and `force_margins` skips negative `tx`. This is a real implementation difference. It does **not yet** prove UR draws wrong pixels; source world origin and domain semantics might differ. First run a read-only clipped-versus-wrapped probe using an existing exact original-USA later-tour course and VRAM/camera witness; change production only if observed correctness demands it.
2. **Anchor semantics differ:** upstream retains up to eight candidate offsets, requires agreement of ambiguous candidates and masks unknown cells; it suspends origin invalidation during `$0BE9` airborne intervals. UR uses a unique calibrated origin and a two-bad-frame transition. Determine whether UR's current state already avoids the upstream failures; accept a change only with one first-frame incorrect-publication or needless-suppression witness.
3. **Sprite positions differ by presentation pipeline:** upstream PPU copy fixes missing 9-bit X bits and hides parked 1P/2P OAM slots; UR's source-visible/effective-OAM and HD compositing policies have independent evidence. Reproduce false-positive sprite scenarios before adapting; final pixel visibility, owner identity, split screen and authentic 4:3 parity govern.
4. **Progression scope differs:** upstream unlock modifies `0x10D3` as a scalar. UR has original-code and snapshot support for a **16-byte per-racer** tier table starting at that byte. The shared first byte is corroboration for one racer, not authority for every profile. Use targeted multi-racer tests if our existing progression/Practice coverage lacks them.
5. **Already corroborated:** 45 RNC1 USA course streams, `$7F:000F` course grid, `$7F:800F` 4×4 records, 32×32 BG1 ring, 16-pixel spatial units, many 1P/2P cameras and ROM identifiers. No new decoder, full extraction farm or duplicate research claim for these.

## First executable experiment: course X-boundary discriminator

- **Question:** when the 16×16 course-world sample lies just left of x=0 or just right of the grid width, is the correct original BG1 tile the modulo-wrapped course cell, masked/blank, or a distinct streamed cell? Distinguish normal race, circular track and P1/P2 viewports.
- **Preparation:** retain the exact native 128 KiB WRAM dump and source-matched original ROM identity; use existing `tools/probe_live_course_world_cells.py` for in-bounds surface-word lookup. Use the new read-only redcomp comparison probe for the two edge coordinate policies. Every output explicitly labels `hypothesis`, not `correct`.
- **Controls:** a unique in-bounds surface cell, a normal no-wrap Dragster view, a later-tour view observed crossing the X edge, and a course/scene reset. For each selected frame collect actual original BG1 VRAM map word and scroll, active map base, line, world/anchor offset and guest rider/camera.
- **Decider:** if actual original raster agrees with wrapped source and current UR outputs blank/wrong pixels, extend the existing materializer with an original-grounded policy and tests. If clipping agrees, record upstream difference as intentional. If evidence cannot disambiguate, retain fail-closed and mark deferred with exact missing fixture; no production patch.
- **Acceptance:** producer source, ROM, original-emulator version, exact frame/route/input, WRAM/VRAM SHA-256, predicted word and original observed word included. Same 256×224 original centre and guest CRCs unchanged. Repeat at 16:9, then 21:9/512 only if first discriminator positive. No release gate or 45-course denominator change from a toy synthetic case.

## Completion protocol and effort economy

- **Wave A, now:** pin exact inventory, source provenance, document code/reference/rights, compare genuinely active WIDE-07/P2 sources and build the *non-authoritative* X-edge diagnostic. This plan and provenance census are initial outputs.
- **Wave B, on evidence:** close RD-02, RD-04, RD-05 and RD-07 with first meaningful source-original differential evidence; implement only when a real defect is shown. Keep local lightweight C/Python checks alongside the existing suite. Reuse existing Windows candidate rather than rebuilding on docs-only changes.
- **Wave C, conditional:** cross-check save, AOT name map, radar/indicator, scene gating, settings and source tools against existing tests/atlas. Import only individually qualified missing evidence. An unresolved first-USA-event problem outranks optional HUD work.
- **Wave D, archival completeness:** classify all 32 OpenSpec capability specs, archived change groups, unique framework deltas, first-party modules and ancillary tooling; record one concise disposition per *subsystem* with source-pinned links and explicit conditional reopening. Compactly preserve negative results and avoid duplicating upstream `docs/history` in UR.
- **Wave E, follow-through:** if upstream changes touch a promoted claim or developer supplies a reproducible bug/correction, diff exact blob SHAs and requalify only affected claim and tests; existing project board owns scheduling. Track mutually informative GitHub conversation without presuming collaboration or access.
- **Stopping conditions:** no live target, exact original proof already present in UR, no meaningful implementation delta, rights block, cross-platform/deferred scope, too expensive relative to first genuine Windows USA event, or uncertainty that cannot alter a decision. Write the result/reopen trigger in existing authority and move on.
- **Closure definition:** all upstream first-party subsystems and unique framework changes have disposition, links to exact source and UR owner, all high-impact divergences have targeted original-USA results or recorded missing witnesses, useful code/tests land through qualified PRs, rights/attribution are correct, and active docs contain instructions rather than a chronology. This does **not** mean bulk copying 1,498 upstream blobs or validating every unrelated framework test.
