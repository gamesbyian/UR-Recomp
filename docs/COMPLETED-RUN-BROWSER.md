# Local Completed-Run Browser and Replay

Status: first usable Windows x64 Modern Local Runs browser/replay plus the first profile-wide Records → Runs/Replays surface implemented. Switch is out of scope.

## Player-facing behavior

During a supported Modern one-player timed Race context, pause the game and open **Local Runs** with **Ctrl+B** on keyboard or **X** on a gamepad. The browser is host-owned and profile-scoped. On a supported settled stock results surface, a host-owned **F8 / Y RECORDS** hint makes the route visible; **F8** or controller **Y** opens the profile-wide Records surface in one action by entering the existing host-owned pause state first. No guest result state is rewritten.

The same wrapper now exposes the first profile-wide **Records → Tracks → Runs/Replays** surface as a permanent **RECORDS** item in the Modern pause menu, with **F8** on keyboard or **Y** on a gamepad retained as direct shortcuts while paused. Its top level now has peer **Tracks**, **Racers/Profiles**, and **Multiplayer/Tournament** views, switched with **Left/Right** or D-pad **Left/Right**. Multiplayer/Tournament now loads the shared multiplayer-run namespace through the fail-closed match catalog: only checksum/course-bound `.urrun` + `.urmatch` pairs become rows, while corrupt, wrong-mode, standalone, or unbound artifacts contribute only an unavailable count. Up/Down selects a stored match, Enter/A opens read-only course/participant/result detail, and Escape/B returns. With no admitted pairs the same destination remains an explicit no-history surface. It still does not infer wins, losses, standings, or tournament results from session-local controller setup or 1P run artifacts. Racers/Profiles is read-only: it loads the authoritative profile catalog, preserves catalogued racers with zero run history, marks the active racer, shows each racer's in-scope run and track counts, and reports the aggregate number of unavailable stored run artifacts when damaged or wrong-scope history exists. Confirming a racer drills into that profile's own **Tracks → Runs → Run Detail** history without changing the active profile or writing profile state. Back returns from that profile's Tracks view to Racers/Profiles. Run-history and detail titles keep the racer identity visible throughout the drilldown.

The Tracks level groups every valid run in the authoritative game/ROM/build/mode scope by stored `course_id`, showing run count, PB, Previous and Previous-vs-PB from the existing canonical selectors. Enter/A drills into that course's chronological run catalog with PB/PREV tags. Confirming a run opens exact run detail with finish, canonical PB and Previous targets, signed finish deltas against both, and checkpoint deltas from the shared presentation model. PB is the default checkpoint target; **Left/Right** or D-pad **Left/Right** switches the checkpoint table between canonical PB and Previous when that target is available. Each checkpoint row shows the selected run's exact time, the selected target's exact time, and the signed delta. Run detail shows three checkpoint rows at once; when a record has more, **Up/Down** or D-pad **Up/Down** scrolls a bounded three-row window and the split header shows the visible range. Changing PB/Previous resets that window to the first checkpoint. Escape/B walks back through run history, Tracks and Racers/Profiles as applicable. Cross-course replay is not synthesized from the currently loaded race. **Ctrl+B / X** hands off to Local Runs only when both the viewed profile is the active profile and the selected Records course exactly matches the authoritative current-course target; cross-profile histories never gain replay authority.

The list is newest-first and shows the stored chronological order, course, local run date derived from the canonical store timestamp, exact 60 Hz finish time, and **PB** / **PREV** status when those canonical selectors apply. Production Records lookup, active-profile resolution and replay staging now use the same `UR_RECOMP_USER_DATA_ROOT` override policy as run capture and the Modern product state; custom user-data roots therefore cannot create an invisible second run namespace. The profile-wide Tracks view also reports any unavailable `.urrun` artifacts, including corrupt/malformed files and valid records outside the current game/ROM/build/mode scope; those artifacts remain excluded from run counts, PB/Previous selection, statistics and replay authority. The catalog layer also now prepares compact per-target statistics directly from those canonical selectors: completed-run count, PB, Previous, and Previous-vs-PB delta, with explicit no-data state rather than a second ranking rule. The selected playable run also shows an exact signed **VS PB** finish delta plus up to two recent authoritative checkpoint rows with exact current time and PB delta, all prepared by the shared completed-run presentation model. Missing/incompatible PB or split data remains `--`/absent rather than inventing a comparison. Corrupt, malformed, unsupported-version, I/O-failed, and playback-incompatible `.urrun` artifacts remain visible as disabled rows instead of disappearing into the valid list.

**Records from the main menu.** On the settled Modern main menu with no other host surface or route active, **F8** opens the same profile-wide Records browser without pausing (there is no race to pause). From the read-only Tour Progress panel (**F7** / mapped **L**), **F8** or physical pad **X** hands off to it (its footer reads `B BACK  F8/PAD X RECORDS`). While it is open the Modern host owns the human input word and holds guest frames, so the stock attract timer cannot leave the main menu underneath. It is browse-only: Ctrl+B / pad X never hand off to Local Runs there, so no replay can be launched from the frontend. Escape/B (or pad Y) closes it with the release latch kept, and a lost main-menu context closes it fail-safe. Native acceptance: `completed-run-replay-acceptance.yml` → *Browse Records read-only from the settled main menu* (`opened=1 paused=0 courses=1 runs=1 local_runs_refused=1 closed=1 admissible_after=1`).

Up/Down or the D-pad moves among playable records while skipping disabled rows. Enter/A launches the selected run. Escape/B returns to the existing paused product surface.

## Replay launch

Replay launch does not add a simulation model. The selected `.urrun` is validated, exported with `encode_completed_run_input_file()`, and staged as the same `INPUT_FILE` grammar already used by deterministic replay acceptance.

A narrow framework hook replaces the current deterministic input stream and leaves it inert until the title arms a race-relative origin. Launch then reuses the existing Modern **Restart Race** lifecycle anchor and resumes through the existing pause path. No course state, racer state, timer state, or arbitrary WRAM is written by the browser.

While a selected replay is running, the wrapper bypasses ordinary completed-run capture so watching a run cannot append a duplicate artifact or perturb Previous/PB ordering. At the observed stock results surface, deterministic input is cleared, the ordinary Modern host is reconciled once, the game is paused, the catalog is refreshed, and the player returns to Local Runs. From there Escape/B returns to the ordinary pause/results surface, where the existing **Exit Frontend** path remains available.

## Ownership and failure policy

The browser is a wrapper around the existing Modern host callbacks rather than a parallel frontend stack. Normal input, pause, options, rendering, restart, and frontend behavior delegate to the existing host unchanged when the browser is closed.

Authentic mode does not expose the browser or replay launch. Two-player/VS and unsupported timed-event contexts remain inert. Playback-incompatible or invalid artifacts cannot be selected or launched. A failure to stage input, load the canonical replay stream, or restore the existing restart anchor fails closed and leaves gameplay authority with the normal guest.

The browser consumes `.urrun` records only. It does not read or modify `.urghost` rendering/projection internals.

## Acceptance

Focused native tests cover newest-first catalog ordering, canonical Previous/PB annotation, invalid/incompatible-row visibility, selection skipping, profile-wide valid-run enumeration, mixed-course Records indexing, course/run/detail navigation, exact selected-run result/split summaries, canonical replay-input staging, invalid-record rejection, and replay return/cancel lifecycle.

The existing completed-run replay workflow now includes those tests and rebuilds the Windows-style native product whenever the browser, replay controller, host wrapper, or live canonical-input reload seam changes. It also seeds one valid captured `.urrun` plus a deliberately checksum-damaged `.urrun` into an acceptance-only run directory, follows the real Modern 1P route, opens Local Runs through the actual wrapper, requires the catalog to report two stored / one playable, launches the valid run through Restart + the canonical live input injector, requires the stock results return, and proves the directory still contains exactly those two `.urrun` files afterward. The established fresh-process deterministic replay comparison remains the independent simulation-equivalence proof. The native consumer gate now independently reloads the production-captured `.urrun` in another process, stages its controller stream through the same `stage_completed_run_replay_input_file()` path as Local Runs, and verifies byte-for-byte equality with the capture-only `.input` sidecar before feeding that freshly reconstructed stream to the actual game. The sidecar is no longer an input dependency for fresh-process acceptance. The native acceptance also re-drives that same persisted `.urrun` under an independently loaded Modern host-state selecting 1× internal rendering, 16:9 Widescreen and VSync off (rather than default 4×, original view and VSync on). It requires canonical run timing, splits and exact controller words to match, compares retained world/pitch ghost samples under the same physical replay contract, and requires an actual visual ghost draw. Only host-owned presentation settings change; the authoritative guest-frame clock and course initializer are untouched. The same manual workflow now includes a separate ordinary-profile Previous-ghost check: a real captured `.urrun`/`.urghost` pair is installed in the profile's `runs/default` namespace, a valid persisted profile selects Previous, and a fresh host process must load and draw that trace without the acceptance-only ghost-source or capture-path overrides. The profile capture path must append a new run and trace, and both are compared with the original captured evidence. These are executable manual acceptance requirements; they do not establish shipping proof until that heavyweight native workflow passes. The replay acceptance also now pairs each real captured `.urrun` with its checksum-bound `.urghost` and requires exact P1 world X/Y/pitch trajectory equality across the original and the replay (allowing only the documented one-frame retirement tail). It reports P1 cosmetic pose and P2 contextual presentation drift independently because the canonical INPUT_FILE stream does not promise deterministic stock presentation RNG. The saved original sidecar remains the sole ghost pose source and is bound to the selected artifact by its checksum; its original movement and pose remain intact when replayed and drawn in a fresh process. Both traces can pass integrity checks but still fail this stronger movement-determinism gate.
