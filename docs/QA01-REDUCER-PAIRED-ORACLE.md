# QA01 replay reducer: genuine paired command adapter

Status: engineering qualification. See docs/CONTROLLER-REPLAY-REDUCTION.md and docs/VALIDATION.md. This adapter does not derive or admit a complete USA event; the release ledger and original independent oracle are unchanged.

tools/qa01_reducer_paired_oracle.py receives --manifest PRIVATE.json --candidate CANONICAL.input --receipt OUT.json. It executes two separate original/native processes for every candidate, requires both to consume that exact controller script, and requires both to write a fresh named full 131072-byte WRAM checkpoint. The manifest binds exact source SHA, original USA retail ROM hash, original emulator executable, original libretro core, native binary, and an explicit already independently validated address/byte discrepancy at one **semantic phase**. At least one original/native equal-state anchor must match before the target can be tested.

The externally specified manifest schema is ur-qa01-reducer-paired-commands/1. It has four pinned file records named rom, reference_binary, reference_core and native_binary, each with path and sha256. reference_engine and source_sha identify the source/engine epoch. The reference and native entries have three fields: argv (executable path and arguments), environment (controlled process environment), and dump (a simple pre-agreed checkpoint filename ending .wram.bin). Both programs must receive %CANDIDATE% and %DUMP_DIR% in their argv or environment. %ROM% may be used to insert the validated original ROM location. The first argv element must be exactly the pinned engine executable (rather than a new untrusted simulation wrapper). A canonical example reference runner uses the existing snesref, a pinned Snes9x libretro core, original ROM, fixed observer SCRIPT, SNESREF_DUMP_DIR and a candidate controller input environment. The native runner uses the existing rebuilt source-bound executable, the same unchanged observation script, and a separately isolated dump root.

The discrepancy object has exact id, phase, offset, original_byte and native_byte. Anchors is a nonempty array of equal original/native 8-bit WRAM expectations, with offset and value. No masking, relative input shifting, overwritten provenance, broad "some error occurred" predicate or auto-selected failure is allowed. Only a fully valid original/native route with the exact named target bytes returns result=reproduced; altered values produce not_reproduced; absent or different authentic stage anchors produce invalid_route. The replay reducer needs a baseline reproduced result and repeats each candidate twice by default. The adapter does not upload any ROM, SRAM or native binary itself.

Use only after the CPU/APU or QA01 source owner supplies an independent **already source-qualified** discrepancy at a fixed phase, confirms both runners truly obey the canonical input script on every candidate, and checks actual guest logs and dumps in an unmodified pilot. Do not use the original movie checkpoint as though controller input poll timing were automatically equivalent between guests. This adapter does not prove input consumption at the CPU instruction level or apply Snes9x OAM conclusions to hardware.

ROM-free adapter contract tests: python3 -m unittest tests.unit.test_qa01_reducer_paired_oracle. Those synthetic subprocesses exercise transport only and cannot supply gameplay evidence.
