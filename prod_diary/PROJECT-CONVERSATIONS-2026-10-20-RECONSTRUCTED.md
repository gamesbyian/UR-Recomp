## Operational coordination and a mutable work board

The user sought ten scheduled positions capable of following a **changing work list** rather than ten hardcoded specialties. They asked how an agent could recover its previous lane and avoid overlapping another agent's work. This led to discussion of stable per-work IDs, per-lane continuity journals, a Drive recovery Vault, GitHub preflight, and manual integration agents that reconcile GitHub and Drive before making decisions. The user explicitly requested configuration, prompt updates, repo changes, reconciliation of vault material into GitHub, and safe closure of eligible PRs including those created by other agents. GitHub merge receipts and issue holds are authoritative for outcomes; the request alone does not establish completeness.

The user's design goal remained recognizable Uniracers in 16:9, controller-first, with source-faithful game behavior. Visual acceptance required screenshots from the actual native executable. The user explicitly prioritized working ahead when CI or a merge was blocked, avoiding redundant work and maintaining provenance rather than declaring visual or physical approval from synthetic checks.
