# Independent P1/P2 provisional model material preview (existing ART-4K Pages viewer)

The one approved viewer surface for experimental 2026 GLB inspection now has a **separate model colourway selector**. The original 1994 sprite player selector and 48-frame rail remain independently controlled; changing a source P1 reference does **not** silently recolour the authored 3D asset. The owner explicitly rejected the current overall 3D likeness, so neither choice is a shipping colour nor evidence of restored 1994 PBR albedo.

**Source-backed engineering scope:** [the real five-pose provisional colourway proof](../../analysis/data/racer-art4k-real-five-glb-provisional-colourway-20261101.json) uses P1 authoring proposal **RGBA(211,43,47,255)** in the single `fork_and_frame__material_0` slot; unchanged P2 is **RGBA(28,89,222,255)**. All 16 source mesh parent geometries/material names remain identical. These are *designer-selected* representative colours, not direct conversion of SNES raster palettes into physical material values. Original P1 and P2 4bpp/RGB pixel evidence proves two distinct 2D chroma families, not the exact 3D fork albedo or which other real GLB parts were originally painted.

This separate Pages control uses the existing published original **source-SHA five-part/16-material GLB gating**. It clones only the relevant imported `MeshStandardMaterial` at runtime for provisional P1, disables vertex-colour multiplication on that clone, and sets the proposed sRGB colour; restoring P2 returns the original exact material object. No GLB buffers, triangle geometry, vertex-colour attribute, material receipts, source camera or persisted file are changed. The preexisting blue-material rim/crank research selector is logically independent; its blue allocation is a deliberately separate hypothetical interpretation, not automatically translated into P1 red because no source original material-part identity has been established.

Switching to another verified named pose, loading an unverified local GLB or clearing the model resets the transient P1 colourway. An actual Chromium source-owned GLB browser test must confirm the red choice visibly changes the 3D canvas pixels, P2 exactly restores those pixels, touch targets are ≥44px, source labels and part census remain unchanged, wireframe survives, and mock/unverified GLBs cannot use it.

**Authoring divergence retained deliberately:** the still-unapproved draft #2832 exporter also offers a separate `p1-provisional-v1` pinkish-red colour `(222,28,89)`. That is a different documented proposal, **not** the real independently geometry-verified `(211,43,47)` variant used here and in `build_racer_colourways.py`. Do not silently mutate versioned export bytes or equate them with authentic original sprite colour; owner review should select a future single authoring palette after actual 3D likeness is acceptable.

No Original/Windows runtime path, release quality gate, ROM, network access, alternate viewer or source-authoring GLB is introduced.
