## Read-only independent acceptance reader

[Checker](../tools/check_qa02_win32_named_full_ntfs_original.py) demands the original, externally pinned GitHub Actions `baldosa-win32-original-real-ntfs-full-game` ZIP, its exact external SHA256, the 40-hex tested product PR-merge source commit, the independently checked packaged CMD SHA256, the exact native C++ fixture SHA256 and the known retail-USA ROM SHA256. It rejects other archives, missing/duplicated/mutated objects, unsafe members and unsigned/unmatched provenance.

The source artifact currently specifies **25 members**: sixteen original raw/typed/selector/catalog byte objects across `before`, `actual-full`, `cold1`, `cold2`; original source baseline, actual NTFS substrate, guest/process and final JSON receipts; and five genuine Windows producer logs. The independent reader recomputes **all sixteen** original binary SHA256/length receipts; separately verifies initial source/base SHA256 and size; requires original complete typed `stock_sram` to decode to the genuine original 8192-byte raw SRAM; verifies unchanged catalog/selector and all four canonical files across the filled-volume attempt and two cold boots; and checks original log evidence of guest frame-2200 race, user-visible save refusal, exit **8**, OS **112** from another genuine Windows process, and two real native boots.

The independent reader is strictly fail-closed: no artifact without all sixteen source bytes and the full original 25-member fixed envelope can be accepted. It requires the same **exact compiled/tested** product source and original CMD/fixture identity as the companion candidate-binding/portable ROM-free package. Its ROM-free unit tests contain only synthetic bytes and deliberate bad SHA, missing-member, wrong-exit and fake-disk-full counterexamples. A green unit suite or green producer workflow alone never grants QA acceptance.
