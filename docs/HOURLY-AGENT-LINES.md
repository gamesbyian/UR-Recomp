3. Execute useful source work, cheap local/ROM-free checks, then appropriate exact-source authentic tests. **Never babysit GHA.** While CI queues/runs, move to isolated documentation, analysis or another necessary line of work. Avoid unnecessary runner saturation.

Otherwise **leave PR open with an updated body/comment stating exact progress, blocker and next discriminating action**. Do not claim tests were run if they were not.
5. Leave a concise handoff in the relevant PR and any owning specialist doc. Maintain single-writer shared queue/ledger policy. Do not spin up new recurring CI workflows for disposable research. No blanket cleanup of branches modified within ten minutes; do not cancel active media work. Such recent changes do not prohibit independent analysis, test runs or fresh branches.

## Continue-until-exhausted execution policy (2026-10-19)

**A commit, completed investigation, submitted PR, CI launch, or status report is a checkpoint, never automatically a stopping condition.** After each milestone, select the next useful, bounded task in either assigned line and continue. Work the second line while CI runs; if both are momentarily blocked, do independent tests, reproducibility, source review, documentation or another available task without colliding with actual writes. The preferred outcome is multiple consecutive meaningful advances per invocation, subject to platform execution limits. **Do not fabricate activity merely to extend a run**, but do not declare completion simply because one small task succeeded. An hourly schedule defines invocation frequency, **not a promised 60-minute execution duration**.

Every final run report must identify: (1) each of the two lines and concrete work advanced, or specific reason for deferral; (2) commits, branches, PRs and exact HEADs; (3) tests actually executed and whether workflows were requested, running or avoided with reason; (4) remaining blockers, next discriminating steps and actionable handoff; (5) **the specific reason execution stopped**, distinguishing a real blocker, exhausted useful work, permission/tool failure, or platform execution boundary. Missing GitHub Actions runs alone are not a defect when existing authenticated evidence suffices. A blocked push is not a reason to stop if independent useful work remains.
