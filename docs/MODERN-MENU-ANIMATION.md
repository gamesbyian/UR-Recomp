# Modern menu animation: source-bound native motion lane

Status: **native Modern/Baldosa root selection motion implemented; original eight-pose racer extraction and opt-in experimental native preview implemented, but default/off and no generated art committed; packaged Windows screenshot and human visual approval HOLD.** This is a specialist presentation handoff, not a release-gate update. The live [work queue](WORK-QUEUE.md), [Modern visual fidelity gate](MODERN-UI-VISUAL-FIDELITY.md) and [character reconstruction veto](HD-RACER-CHARACTER-RECONSTRUCTION.md) remain authoritative.

## Scope and actual native integration

- `native/product/modern_menu_motion.hpp` owns deterministic animation state. Its only mutable values are host-visible selection and presentation ticks. It is not a gameplay state machine, does not mutate the selected Modern destination, and is reset when root is not visible. Same inputs and clock produce the same pose.
- `native/product/uniracers_modern_host.cpp` **and** `tools/baldosa_native_modern_root.cpp` call that module only for Modern root after the shared presenter. The Baldosa call suppresses ornament behind quit, Practice, 2P join, Records, profile and Options modals. The legacy host also retains its original isolation. Both draw in the actual existing compositor; no new UI router.
- `native/product/uniracers_modern_host.cpp` calls that module **only after** `render_modern_root_overlay()` for the existing Modern root. The painter writes a 2-logical-pixel source-blue selected-row accent with subtle phase-based geometric breathing, deliberately avoiding unsupported rapid colour flashes to the actual host compositing buffer, inside the existing root panel. It does not replace root composition or routes. The host's SDL ticks feed a 60Hz UI clock when the guest is held; no guest frame, SRAM, CPU state or authoritative input advances for animation.
- `UR_REDUCED_MOTION=1` disables cursor spin, selection travel, entrance and hero offsets while retaining immediate selected-state identity. The flag is a temporary host-level preference. A persisted player-facing Options setting must be separately authorized and implemented against the current actual Options capability model; do not add a fake control.
- `UR_MODERN_MENU_TEST_TICK60=<decimal>` pins the *absolute* UI tick for a static Modern root capture; **on its own it freezes transition age at zero on first root entry**. For an actual native 60Hz motion sequence, set `UR_MODERN_MENU_TEST_ADVANCE_PER_PRESENT=1` **as well**: the first real visible root paint uses tick N, each following real root compositor paint increments exactly one UI tick. **The compositor draw ordinal is not automatically the SDL present ordinal**: source-bound QA must match P6 native paint and final SDL P7, and must not assume one-to-one draws/swaps when proving final output. This produces exact reproducible native 0–39 entrance-phase poses and 0–12 source cursor motion regardless of wall-clock jitter. A hidden root, modal or quit confirmation resets the host-only visible-present counter; no synthetic game frames or inputs are injected. The Baldosa native host now emits an opt-in log line on each genuinely painted root presentation, prefix `UR_MODERN_MENU_MOTION_CAPTURE`, recording `ordinal`, `tick60`, `selection`, 16-phase cursor `spin`, interpolated marker `offset`, source-model `entrance` remaining, `reduced` motion, exact root X/width and physical surface width/height, and `painted` success. These logs are **only** emitted with a valid numeric seed and the explicit per-present stepping flag, not in ordinary player builds. The sequence must retain actual root-present ordinals, selected-state actions, source/EXE hash, viewport and SDL/P6/P7 readback provenance in the QA manifest. It is not equivalent to unmodified wall-clock kinetics, and the current title/root renderers do not yet animate the entire BG2 entrance-distance. The two environment variables are acceptance harness inputs, never player settings.
- Invalid/overflow capture decimals fail closed to ordinary monotonic SDL-derived presentation time in both modes. Saturated `uint64_t` addition prevents test counters wrapping backwards. Neither capture clock affects guest/physics/tour clocks, input, SRAM, replay or Authentic mode.
- The composition parameters `ModernMenuMotionAnchors` default to the current root at selected row Y=57, row stride=21, marker X=5. A root/screen agent moving or redesigning rows should update the narrow paint call and anchor together rather than inheriting out-of-date pixel assumptions.
- `native/product/modern_menu_stock_hero.hpp` is a **real native ARGB raster compositor**, complete with 1x through 4x nearest stock reproduction, alpha compositing, bbox guards, provenance admission and one-shot pose/hold rendering. It cannot draw unverified or procedural 4× art. A compiled source asset is optional; ordinary builds have none. Unlike the unapproved 4x procedural engine assets, a validated sequence of full **original stock 64x64 pose rasters** can be admitted without changing this renderer. The pinned Baldosa host has an explicitly opt-in preview: with a generated verified original header at build time, `UR_MODERN_SOURCE_HERO_EXPERIMENTAL=1` paints the stock pose experiment on the 342-wide root and displays **ORIGINAL ART TEST**. At 256-wide / 4:3 it remains unavailable pending safe composition. Without a generated header the hook compiles out entirely, so no artwork is smuggled into the default build. This is an experimental original pixel hero, **not a finished showroom**.

## Source, duration and credibility

`analysis/generated/menu-visual-language.json` measures original 16-frame cursor spin at two ticks per tile (32 ticks), single-row source move steps `6,4,3,3,2,1,1,1,1,0,0,1` (12 ticks) and BG2 256px screen slide in 39 ticks. The pure model preserves these as values; it normalizes the 23px measured movement to the current Modern 21px row step. Modern's measured stock-grammar yellow/blue presentation roles come from `native/product/modern_stock_menu_palette.hpp`.

The provisional cursor ornament keeps the original OBJ's blue color constant. Selection easing consumes the source's **first six-pixel move immediately in the key/gamepad press frame**, normalized to the native 21px pitch, and preserves the actual displayed marker location during immediate reversals. Reduced motion completes both the entrance and pending selection travel in place; turning animation back on does not restart a stale entrance, but a newly pressed selection can animate again. A one-pixel height/inset change twice per source 32-frame cycle supplies gentle idle feedback; **it is not a reconstructed 32×32 dimensional source cursor**. Source art and cursor-shape approval remain separate from the timing model.

The stock cursor evidence proves **cursor timing**, not unicycle pedalling/flip cadence. The one-shot pose cadence is now derived directly from original source-observed guest frames 1213..1220: one pose per 60Hz tick on root entry/selection change, then hold frame 1220 rather than fabricating a 1220→1213 loop. The low-amplitude 64-tick host bob and brief lean remain independently proposed composition animation and require visual approval. The verified clip is a real race pose window, **not verified title/idle actor movement**, so it stays visibly labelled experimental and opt-in. The entrance-distance value is available to title/screen agents but not currently applied to the on-screen root panel. Authentic mode and simulation/race animation remain untouched.

### Stock hero admission contract

Before binding even the smallest live hero sequence:

1. Extract registered **Original** composited 64x64 ARGB rasters via the existing `tools/extract_racer_presentation_family.py` / `analysis/data/racer-hd-replacement-prototype.json` original-corpus path, with source ROM identity, source registration, per-frame buffer hash and semantic frame ID. A `verified=true` field alone is not independent source proof.
2. Qualify the intended **ordered** pose sequence across adjacent original visible frames, including source OAM/PPU composition, palette and cadence. Never infer order from ascending semantic IDs or confuse a 4x authored pose for a stock frame.
3. Store a reviewable original pose sequence manifest plus provenance. Supply ARGB 64x64 buffers and digest to `ModernMenuStockHeroSequence`, with `original_raster_source_verified` and `original_pose_order_verified` only once established. The renderer prevalidates **all** pose buffers, semantic IDs and FNV integrity before touching the framebuffer and fails closed on any mismatch.
4. Obtain original-character art comparison and user approval on exact native screenshots. Pixel-perfect 1x stock drawing proves technical source identity, **not** artistic approval for new high-resolution art. The October 10 **4x procedural character-likeness veto** remains in full effect.
5. Wire that sequence only in a safe 16:9 / compact 4:3 region chosen by the screen owner. Do not paint a hero over controller reachability, selected option, records text or modal.

### Reproducible original-raster clip export (no repository art commit)

The new `tools/build_modern_menu_stock_hero.py` accepts only the canonical USA retail ROM SHA-256 `859ec99fdc25dd9b239d9085bf656e4f49c93a32faa5bb248da83efd68ebd478`. No invented pose order, synthetic asset, arbitrary palette, cycling or HD reconstruction.

Run from the repository root, only in an authorized private workspace:

```bash
python3 tools/build_modern_menu_stock_hero.py \
  --rom reference/roms/retail/Uniracers_USA.sfc \
  --header native/product/modern_menu_stock_hero_original.generated.hpp \

```

Generate the header **before building** the native executable, and explicitly compile the Baldosa native root with `-DUR_MODERN_SOURCE_HERO_EXPERIMENTAL_BUILD=1` (for example, with an isolated experimental `CXXFLAGS`/CMake build). The build refuses the opt-in flag if the generated sprite header is absent. Even in that special build, the native overlay remains off unless `UR_MODERN_SOURCE_HERO_EXPERIMENTAL=1` is set at runtime. Normal Windows binaries do not embed this experimental ROM-derived pose strip, even if a developer has a generated header left in the worktree. Its exact pathname is ignored by git deliberately so a ROM-derived raster is not accidentally submitted. Optional review PNGs are genuine 64×64 original-raster pose plates with manifest-bound SHA-256, **not screenshots of the final native game**. The opt-in runtime experiment composes this source image at nearest-neighbour 4× on the 342px native root. Its alpha-safe overscan admits only fully transparent canvas padding outside the physical surface; an opaque pixel anywhere outside the safe rectangle in any registered pose refuses the entire draw. The original P1 source colour is fixed: this WIP is not yet a live profile/appearance preview, and no final acceptance may assume it matches the selected Modern racer. `tests/unit/test_build_modern_menu_stock_hero.py` independently rebuilds the true output in a disposable directory and compiles the resulting C++ on the precise source corpus when the ROM is available. No generated hero header or source pixels have been committed, and no native executable has yet been built from this optional generated header in this branch.

### Original 32×32 spinning OBJ cursor reconstruction (additional source work)

`tools/reconstruct_modern_menu_cursor.py` now consumes the **actual source PPU dumps** from the established `tests/input/menu-visual-language.script` capture, checks every one of its 64 chronological idle samples, OAM palette 7 arrow and palette 5 shadow, measured tile phase order `8,4,0,204,200,196,192,140,136,132,128,76,72,68,64,12`, two-frame holds, exact seven-pixel shadow displacement, original CGRAM colours and 32×32 OBJ tile geometry. It reconstructs a 16-phase 39×39 RGBA review atlas and SHA-bound dump manifest, rejecting missing or reordered captures and incomplete raster tiles. The regression test uses **clearly synthetic** VRAM/OAM to test decoder math and deliberate rejection paths; those test pixels never enter the product.

The independent original-OBJ atlas decoder has been corrected against the SNES $2101 OBJSEL hardware rules and the shared visual grammar's source loader: name base advances by **0x2000 VRAM words per step (16 KiB)**, while the optional secondary name page advances by **0x1000 words per step (8 KiB)**. It also validates that the actual OAM size pair selects a true 32×32 large sprite, rather than assuming the OAM large bit determines dimensions by itself. Original OAM horizontal and vertical flip bits are now resolved unambiguously from the full 544-byte source OAM table and reflected across the **whole 32×32 sprite**, not per 8×8 subtile. A two-tick phase-hold or repeated 32-tick revolution with contradictory OAM flips is refused; dedicated one-pixel corner tests cover H, V, both and unstable-pair rejection. The source tool also re-rasterizes **all 64 original OAM/VRAM/CGRAM captures** (not only the first of each pose), checks every two-tick bitmap hold and confirms the complete 32-tick second revolution repeats the first exactly. Changing VRAM on the unsampled half of a source pair, or the source shadow's measured palette-five pen, fails closed with an explicit test. A synthetic VRAM-bank relocation regression proves that a nonzero name base changes the actual decoded source bank while retaining identical cursor pixels. These arithmetic corrections are source-decoder contracts, not permission to ship any source atlas. The required original 64 PPU source dumps are not retained as files in the git repository, so the tool cannot yet produce a source-qualified original OBJ atlas in this environment. To run on a real source capture:

```bash
python3 tools/reconstruct_modern_menu_cursor.py \
  --dump-dir /path/to/source-mvl-dumps \
  --out-dir /tmp/original-cursor-review \
  --manifest /tmp/original-cursor-evidence.json
```

The recovered sprite's actual appearance must be visually checked against original menu captures and native selection placement before it replaces the provisional two-pixel source-blue accent. The 32×32 source cursor, its +7px shadow and wide-screen layout are owned jointly with the shared visual grammar / root composition agents in #2038 / #2040. **No decoded original cursor is yet active in the native game.** This is source-reconstruction tooling only, not evidence of verified release artwork or final 4:3/16:9 screenshots.

### Independently verifying real native motion receipts (P6 only)

The source-bound Modern root can emit `UR_MODERN_MENU_MOTION_CAPTURE` rows during a private test build/run when **both** `UR_MODERN_MENU_TEST_TICK60=0` and `UR_MODERN_MENU_TEST_ADVANCE_PER_PRESENT=1` are set. The new `tools/verify_modern_menu_motion_capture.py` consumes this **actual native log**, compares its 32-tick cursor spin and 39-frame entrance-distance model against `analysis/generated/menu-visual-language.json`, and checks the source-grounded logical menu geometry: 256×224 with root (x=8, width=240) or 342×224 with root (x=11, width=320). This deliberately makes a wrong 240px wide-root marker placement fail. Source entrance distance is a **model field**, not an on-screen proof of a 256px BG2 root transition.

```bash
python3 tools/verify_modern_menu_motion_capture.py \
  --host-log /path/to/exact-native-host.log \
  --out /tmp/modern-menu-motion-native-receipt.json \
  --min-frames 40
```

The verifier refuses dropped/duplicated draw ordinals, discontinuous injected UI ticks, changed viewport mid-sequence, bad stock spin phases, wrong 39-frame curve, invalid selection/rectangles and painter failures. **It now validates the exact signed marker displacement in every draw**, not merely whether successive offsets changed by a plausible amount: source-normalized adjacent motion, immediate first-frame response, physical continuation through rapid opposite selection and snapping on nonadjacent/wrapped selection must all match the 12 original source increments. It also correctly accepts negative `offset=%d` values from the native renderer and source-required `spin=0` when reduced motion is enabled. **By default it demands one contiguous root session of at least 40 real native compositor draws; a second ordinal-zero frame is rejected, not silently treated as a fresh session.** For a documented multi-session native path, `--allow-multi-session` permits distinct sessions only when each independently meets `--min-frames`; the reviewer must separately furnish host hide/reentry evidence, which this parser cannot establish from a bare draw log. It also recognizes reduced-motion suppression of an unfinished entrance (including correct non-restart after the preference is switched off). `tests/unit/test_verify_modern_menu_motion_capture.py` covers malicious and truncated log data, both layout sizes, two root sessions, independent CLI JSON output and source-manifest cadence corruption.

**Evidence boundary:** these are **native root compositor draw receipts**, not SDL P7 presented frames, audio/SFX kinetics, real controller input proof, all guest frames or visual/art approval. QA #2041 and integrated #2053 must correlate source-bound P6 draw events to the *separate* actual SDL readback on one exact Windows PE, keeping every untouched image hash and viewport. This tool does not manufacture art, simulate native draws, certify human review, or advance guest execution.
