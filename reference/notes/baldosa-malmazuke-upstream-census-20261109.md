## Code- and PR-body-specific findings from the second pass

- **Baldosa split-screen regression, [10b864b9d](https://github.com/baldosa/uniracers-recomp/commit/10b864b9d14a7b7416dd909eb7b054c88faef101):** `src/main.c` sets `g_hdma_oamdata_at_10c=true`, alongside an exact `snesrecomp` submodule bump to `075fbe4c8e0d97b0013be541795c39cb644a9709`. The new `tests/routes/race_2p_split.txt` captures high OAM at two-player checkpoints and `tools/compare_dumps.py` compares OAM when both original/native dumps exist. **UR already documents the 0x10c OAM word address = 0x218 high-OAM byte, lines 0/112 and source-visible P1/P2 visibility** in `reference/notes/oam-active-display.md`, so this is a potential missing *exact-host regression check*, not a new underlying behavioral discovery. Check whether current Windows backend enables the identical framework behavior before proposing source work.
- **Baldosa browser diagnostics, [b4f5928ea](https://github.com/baldosa/uniracers-recomp/commit/b4f5928ea1efc421ed39500535be7f9f13866f58):** `src/web_debug.c` exposes native audio underflows, missing output frames, drops, occupancy, produced/consumed samples and browser loop stats to `?debug`. Reuse the *diagnostic vocabulary* if Windows audio glitches emerge; the Emscripten bridge is inapplicable as-is.
- **Malmazuke original-name filtering, [#87](https://github.com/malmazuke/unirally-reconstruction/pull/87):** 71 source-listed prohibited words are checked on stock keyboard OK; eight-letter rider and 8–17-character league names can commit one or two PAL frames later due to CPU work. This is scoped Authentic-menu behavior; Modern host user-entered names have a different deliberate policy.
- **Malmazuke league overrun, [#88](https://github.com/malmazuke/unirally-reconstruction/pull/88) / [#91](https://github.com/malmazuke/unirally-reconstruction/pull/91):** original league pair standings and dense RECORDS percentages can cross an NMI/frame wait, with timing dependent on name length, tie ordering, palette work and sound-queue polls. Upstream's podium-return timing remains unresolved. Do not transplant PAL cycle estimates into USA 60 Hz without source clock and input-phase validation.
- **Malmazuke split HUNTER, [#89](https://github.com/malmazuke/unirally-reconstruction/pull/89), [#90](https://github.com/malmazuke/unirally-reconstruction/pull/90):** two-view graphics include invisible rider/track effect, lower-view mosaic, caption order and slow-motion update gaps. Crucially, the original branch around PAL `$81:94A8` applies HUNTER power-bounce landing matrix 0 to **either** rider in two-view races when option `$77:0750` bit 3 is set; one-view opponent semantics differ. Strong conditional USA 2P state/renderer lead, not an automatic guest patch.
- **Malmazuke option transitions, [#92](https://github.com/malmazuke/unirally-reconstruction/pull/92):** named `$77:0742` / `$77:0750` bit readers/writers identify clearing a title-code flag on league/VS entry and clearing a pending podium bit when leaving the league slot screen. These can affect *later boots* and league results, so include cold-save causality in the cheapest USA checks.
- **Malmazuke evidence storage, [#85](https://github.com/malmazuke/unirally-reconstruction/pull/85), [#86](https://github.com/malmazuke/unirally-reconstruction/pull/86):** an explicit task evidence budget, verified transparent compression/APFS clones and `.zst` capture readers reduced many gigabytes of local captures. This is a methods comparison, **not** permission to delete currently authoritative UR witnesses.
- **Malmazuke SDL source integrity, [#98](https://github.com/malmazuke/unirally-reconstruction/pull/98):** pin-verified SDL3 3.4.10 archive fallback from GitHub release to `libsdl.org`, still bound to `URL_HASH`. Only relevant if UR's exact dependency-fetch path suffers a comparable outage.
