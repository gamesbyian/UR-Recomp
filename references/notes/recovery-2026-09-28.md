## High-value technical discoveries

### Exact active-display OAM mechanism
jgenesis issue #164 reports Uniracers Vs.-mode OAMDATA writes:
- scanline 0: `0xA5`
- scanline 112: `0x5A`

Both target high-OAM byte `$18`, affecting sprites 96–99. The game alternates which sprite pair is onscreen in the top and bottom halves.

This independently lines up with:
- Snes9x forcing OAM address `0x10C`
- MAME routing active-display OAM access to byte offset `0x0218`

Those are equivalent addressing views of the same location.

### Broader historical Snes9x compatibility seams
The older changelog shows Uniracers exposed multiple emulator-accuracy problems:
- LoROM SRAM mapping
- XOR-window / area inversion behavior
- color-addition / empty-subscreen behavior
- later DMA/OAM active-display behavior

This means recomp validation should have separate tests for each subsystem rather than treating every rendering issue as the OAM quirk.

### Native TAS WRAM watchpoints
Halamantariel published these addresses in 2008:

| WRAM | Format | Meaning |
| --- | --- | --- |
| `7E:04B7` | signed 16-bit | speed |
| `7E:11CD` | unsigned 16-bit | booster meter |
| `7E:0411` | unsigned 16-bit | X position |
| `7E:0415` | unsigned 16-bit | Y position |
| `7E:1509` | unsigned 8-bit | screen X position |
| `7E:11FD` | unsigned 8-bit | flips |
| `7E:11F9` | unsigned 8-bit | rolls |
| `7E:0F61` | unsigned 8-bit | twists |
| `7E:042B` | unsigned 8-bit | Z-flips |
| `7E:042F` | unsigned 8-bit | tabletops |

These are unusually strong symbol-reconstruction anchors because they were explicitly used as TAS memory watches.

## Important unfinished experiment

An attempt was made to scan the repo's 2 MiB US ROM directly for ASCII `RNC` headers. GitHub exposes the ROM file metadata but does not inline the bytes through the connector API at this size, so no valid scan result was obtained. Do not interpret that failed attempt as evidence for zero RNC headers.

The next good route is to run a small scanner through a checked-out/mounted repo or CI workflow and compare candidates against the preserved ProPack decoders.
