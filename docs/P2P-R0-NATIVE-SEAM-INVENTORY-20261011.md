## Two distinct simulation clocks must not be conflated

The post-run callback's `stats->frame` belongs to the host's execution timeline; native Restart rewinds guest state while preserving an append-only host time record. A remote input packet must identify the **session epoch** and a canonical **guest simulation input index**, not a UI frame, wall-clock timestamp, painted frame count or a guest frame filename that can be overwritten on rewind.

The established mapped input capture begins when the race is actually observed, records the next input frames, and includes the transitional non-race frame before terminal settlement. Its local `captured_input_frames_` is an archival race-relative counter, **not proof of a globally synchronized network tick**. R1 must define and test an explicit pre-step index: one initialized guest state, step 0, each matching 2P input pair, and end-of-event checks at identical logical state boundaries.

## R1 admission checklist: independent processes, no network yet

1. Establish an exact compatible build/ROM/core identity, starting cartridge SRAM, initialized CPU/PPU/APU/WRAM/VRAM/DMA state and stock title state for both independent processes. **Never seed a user's long-lived profile by overwriting their save**; use isolated disposable user-data roots and the existing pinned USA ROM verifier. Keep optional visual settings out of gameplay compatibility when empirically safe.
2. Exercise the **existing** Baldosa pinned two-seat guest route under identical source-mapped input streams in independent processes. Use original 60 Hz guest tick semantics, not the Windows presentation FPS, host frame or wall-clock. Reuse existing scripted routes and native smoke rather than creating a new emulator/harness.
3. Compare authoritative guest state before step 0 and after every step or a justified checkpoint cadence: complete 128 KiB WRAM, 8 KiB SRAM, CPU registers/status/stack, PPU/VRAM/CGRAM/OAM/HDMA/DMA, APU state, timers/RNG and any other execution-affecting memory. `g_ram` and WRAM CRC are **necessary diagnostics, not sufficient parity proof**. Record what the existing native snapshot API actually contains; never assume “rollback” in its symbol name means network-safe arbitrary rewind.
4. Divergence output must identify exact guest tick, first differing subsystem, input pair, initialized state digest and executable/ROM hashes. Reduce to smallest witness, and prove negative controls by flipping one P2 button bit and then one initial-state byte. Pause and Restart are session-boundary experiments, not silent tick alignment repairs.
5. Repeat first using the same Windows build, then cross Windows/macOS **only when** a real macOS backend exists. Confirm same guest result, winner, course, and source-settled result data; don't infer event acceptance from early matching CRC snapshots. Source-verified original/native QA-01 is a distinct gate.
6. **Only after this succeeds:** prototype a bounded offline packet-delay shim on the real input authority (never guest physics) with duplicate, late, reordered, missing, replayed and forged frames. Start with delayed lockstep. Avoid automatic host state rewinds until safe side-effect-free rollback is separately demonstrated.

Expected R1 output: command/fixture identifiers, pinned build/runtime/ROM IDs, two independent process launches and dumps, machine-readable input & state checkpoint manifest, a passing event and deliberate failing event, explicit missing state domains. A source-anchor PASS from this R0 audit cannot promote any of those claims.

## Independence and impossibility checkpoints

Discovery (e.g. DHT/PEX), NAT reachability and race traffic are three different responsibilities. Manual LAN/IP/invitation remains an unconditional usability path and an essential *extinction-recovery* option. There is no way to discover another person's fresh endpoint from **zero shared information**. A relay can be an ordinary consenting player's publicly reachable instance, subject to explicit opt-in, resource limits and authentication, but some NAT/firewall combinations cannot connect if no such instance exists. No Steam/PeerJS/hosted certificate authority, obligatory developer domain, always-on coordinator or proprietary account is an acceptable required dependency.

A future portable handshake should pin: independently generated peer key, protocol major/minor and capability bits, canonical guest build/ROM digest, deterministic tick policy, replay nonce/session epoch, both controller seat assignments and a derived shared initial-state digest. Never accept user-controllable JSON or discovery advertisements as authoritative guest code or game-result input. **R8 wire bytes must be separately specified and independently implemented**; this inventory does not quietly invent the protocol.
