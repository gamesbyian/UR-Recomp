**Executed source original Snes9x first CPU `$2140=$CC` write:**

- CPU beam `V=119, H=312`; `spc::reference_time=266`; `spc::remainder=128292`; numerator `15664`, denominator `328125`.
- `S9xAPUGetClock(CPU.Cycles)` **predicted 2 SPC cycles** to consume from the 65816 bus clock, while the actual source `S9xAPUExecute()` advanced the independently instrumented SPC from age **103322541 to 103322546, 5 cycles**, before `SNES::cpu.port_write` made `CC` visible. Thus an **actual +3 SPC-cycle source opcode-boundary overrun above its requested fractional charge** was witnessed at that very port write. Because Snes9x `SMP.enter` executes opcodes to its internal clock threshold, the requested fractional charge need not equal the cycles consumed before returning to the CPU's port write; it is unsafe to treat a native precisely timestamped queue write as source-equivalent solely by integer age.
- The archived loop has **nine** original CPU CC writer records at scanline H `312, 410, 508, 646, 744, 842, 940, 1038, 1136`. Their respective observed SPC increments are **5, 4, 5, 6, 2, 3, 4, 5, 4**, while requested charges are **2, 3, 3, 3, 4, 3, 3, 4, 3**. These are per-APU-execute intervals, not a proof that every opcode lasts that many cycles or that an instruction was already in flight at each particular CPU bus write.

**Interpretation and limits:** This is the first executed original-side observation connecting fractional CPU clock calculation, the return from `S9xAPUExecute`, and the *actual* first CC port write. It strengthens the source-specific hypothesis that **whole-opcode SPC execution vs precisely timestamped queued CPU writes** causes the nine-cycle ready-loop phase difference. It does **not** yet prove a uniquely correct alteration: original and native CPU/SPC clock axes have separate anchors, and source opcode-execution overrun may include previous fractional debt/phase. RF-029 advanced only the SPC port read and RF-031 globally deferred all equal-target writes; both worsened memory parity and remain closed negatives. No speculative one-cycle or whole-opcode global timing intervention is justified without tracing the particular SPC PC/cycle fence at the CPU write, A/B source-visible first CC result and all strict gameplay/WRAM/SRAM gates.
