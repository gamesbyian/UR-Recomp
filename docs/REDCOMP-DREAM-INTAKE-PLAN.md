## Initial independent comparison: findings requiring adjudication

1. **X-boundary mismatch, unresolved:** upstream `WsSrcCell` normalizes `tx %= s_src_cols` and wraps negative X; UR `ur_ws_course_tile` refuses `cell_x < 0 || cell_x >= coarse_w*4` and `force_margins` skips negative `tx`. This is a real implementation difference. It does **not yet** prove UR draws wrong pixels; source world origin and domain semantics might differ. First run a read-only clipped-versus-wrapped probe using an existing exact original-USA later-tour course and VRAM/camera witness; change production only if observed correctness demands it.
2. **Anchor semantics differ:** upstream retains up to eight candidate offsets, requires agreement of ambiguous candidates and masks unknown cells; it suspends origin invalidation during `$0BE9` airborne intervals. UR uses a unique calibrated origin and a two-bad-frame transition. Determine whether UR's current state already avoids the upstream failures; accept a change only with one first-frame incorrect-publication or needless-suppression witness.
3. **Sprite positions differ by presentation pipeline:** upstream PPU copy fixes missing 9-bit X bits and hides parked 1P/2P OAM slots; UR's source-visible/effective-OAM and HD compositing policies have independent evidence. Reproduce false-positive sprite scenarios before adapting; final pixel visibility, owner identity, split screen and authentic 4:3 parity govern.

### RD-12 source-bound negative: scalar unlock versus rider-specific progression

**Disposition: conditional method reference; reject direct import of the upstream unlock implementation.** At pinned USA redcomp-dream `dc3d1edfd7a8e86921fd5ac35b1525e8069302ed`, `game/src/variables.h` names `kSramTourStage = 0x10D3` and `kSramTourStageAll = 3`. `game/src/uniracers_save.c::SaveUnlockTick` unconditionally targets **that one byte**, when the setting is on, the save passes its signature/five-block checksum predicate, the emulator is not in netplay, and the current value is below three. It changes active guest SRAM permanently on exit. `tools/scripts/save/srm.py::cmd_unlock` similarly changes only the first tier byte in an output copy; the upstream `docs/formats/SAVE_FORMAT.md` reports a value-sweep on its test saves and describes a scalar tour-stage presentation. These are real source facts but limited original-game observations.

The UR source-backed `docs/knowledge/progression-sram-and-results.md` identifies the same byte as **rider 0** in the per-rider tier table `0x10D3..0x10E2`, with a second table `0x10FD..0x110C`. Tier selection is computed from the **selected rider's** medal rows, with tier 1/2/3 thresholds; the recovered all-silver and With Hunter snapshots and explicit original code are the existing authority. In particular, the upstream guard `SaveImageValid` tests five checksummed blocks before writing, while UR's documented stock boot compares the **12-byte magic only**; these are distinct admission policies. This does **not** independently prove redcomp's unlock behaves incorrectly for rider 1, nor that its direct write immediately changes the game UI, because its reported save-based observation is narrower than a two-rider original/runtime witness.

**Cheapest discriminating witness if an actual owner feature requires unlock:** take a separate test save with distinct rider-0 and rider-1 medal/tier state; capture original-USA selected rider, PICK TOUR page and SRAM `0x10D3..0x10E2` plus mirror `0x10FD..0x110C` before and after selecting each rider, after progression, and after a cold reload. Compare the upstream one-byte edit and any proposed UR host behavior against an otherwise identical *unaltered* control and stock-original outcomes. Assert unchanged other-rider progression, no checksum/signature damage, no unintended persistent cheat and no netplay guest mutation. Keep this in the existing progression/Windows profile owner, with source and exact-USA proof; don't create a new save engine, add a separate queue or turn a vendor implementation choice into a game requirement. **Reopen only** on a real multi-rider unlock request or a current original/native discriminator; do not spend the WIDE-07/first-event critical path on an unrequested feature.
