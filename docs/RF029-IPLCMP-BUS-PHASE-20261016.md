# RF-029: original/native Zoo IPL ready-compare cycle discriminator (research only)

**Owner:** CPU/APU source causality for #1689; independent QA-01 retains event acceptance. **Status:** opt-in, deliberately scoped experiment, not an accepted fix. The old nominated Windows ZIP, Modern, graphics and release ledger remain untouched; **USA complete-event count 0/45**.

## Falsifiable timing premise

The executed CPU/APU local observation in [RF-028](RF028-INTERRUPT-ENTRY-COST-20261016.md) shows an NMI-disabled sound-driver IPL protocol restart during genuine Zoo frames +5034..+5046: CPU writes port $2142=00, $2143=04, $2141=01, repeatedly writes $2140=$CC, and awaits SPC echo. On the composite research stage, the original/native first $CC reaches SPC at ages 103,322,546 / 103,322,541; the SPC first sees it after 8 / 2 further cycles, and the CPU makes 9 / 7 ready polls. The difference leaves a one-byte native lead in WRAM `7E:0063` only at source-relative +5040 (`73/74`) and +5045 (`B3/B4`), with all 13 `7E:0069` samples equal. Those WRAM values and the clean +5039 frame are independently confirmed by [QA-01 exact composite ELF](QA01-COMPOSITE-EXACT-ELF-ZOO-HANDOFF-20261016.md), run 38884542449.

The exact pinned Baldosa IPL ROM embeds `78 CC F4` at SPC `FFCF`: `CMP $F4,#$CC`, **5 cycles**. Snes9x's cycle-stepped SMP source (`apu/bapu/smp/core/oppseudo_read.cpp`, opcode `0x78`) performs opcode fetch, immediate fetch, DP address fetch, port read, idle; the port read therefore occurs on **cycle 4**. Baldosa's RF-026 deliberately collapses all accesses within an opcode onto its **last cycle**. For this instruction it reads $F4 on cycle 5. The CPU's queued write landing between those two cycles would be observed by native one cycle prematurely. This is a specific structural cause to **test**, not proof that this opcode was executing at the decisive Zoo sample.

## Isolated test treatment

`tools/baldosa_spc_ipl_cmp_cycle_patch.py` applies only after RF-026 and only to the pinned disposable Baldosa checkout. When IPL ROM is visible, the SPC is at `FFCF` on DP page zero and the base cycle countdown is 5, it samples the port at cycle 4, stores the sample and consumes it exactly once on the fifth-cycle comparison at `FFD2`. No core ABI change (reuses serialized reserved APU `pad[2]/pad[3]`), cycle insertion, unrecognized opcode changes, input shift, SRAM edit or alternate game host. Reset clears the reserved pad. A compiled C unit test simulates CPU $CC arriving between those cycles and requires the earlier, single original-style read rather than RF-026's later value. The small patch is deliberately **not** a full hardware SPC bus-cycle model and not a production implementation.

One existing, source-qualified original/native Zoo campaign with RF-015..019 + RF-021/023/024/026/028 serves as treatment base. The new manual-only boolean `baldosa_ipl_cmp_cycle` is legal **only** with that entire research stack, Zoo, unmasked 78-checkpoint full WRAM mesh, contiguous 13-frame sound window, true source followthrough and next Bowl. Existing default and release workflows never stage RF-029. Independent baseline is the exact original/native composite run 38884542449 (binary `9a3bd17afd8377a4c83e76c05cd57dfdae2488e498aa4bea1b90a2baa018bb48`). The new native ELF is distinct by design and must have its own checksum.
