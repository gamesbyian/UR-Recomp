## Why the next P2 optimization should not chase Practice alone

Both consumers begin after the one-build producer and run in separate hosted Windows jobs. For a fixed candidate/producer and ignoring scheduling noise, consumer makespan is approximately

`max(seed-dependent group duration, independent group duration) + aggregate / handoff overhead`.

In the **single observed two-worker hosted comparison**, the independent job took **301s** and the seed-dependent job **332s**. The critical consumer is therefore the **seed** group. A further isolated reduction of Practice/independent by 1, 30 or even 100 seconds produces **zero modeled consumer-phase reduction** as long as seed remains 332s and independent stays below it. With independent fixed at 301s, the upper bound from reducing seed alone before becoming independent-limited is **31 seconds**, minus new setup/handoff costs and subject to actual queue/VM variation. These are **conditional bounds from one run**, neither a forecast nor proof of savings.

[#3238](https://github.com/gamesbyian/UR-Recomp/pull/3238) attacks a different possible bottleneck: original seed-producing case 0 must finish alone, then original cases 1 and 2 may be independent *readers* of exactly the same 8KiB SRAM. Their historical serial durations (~27s each) set only a **hypothetical** overlap opportunity. Live source inspection must check that no script writes a common path, uses uncontrolled shared Windows state, changes original ordering/assertions or silently races seed data. A before/after digest cannot prove that no transient mutation occurred, and two threads returning in canonical order does not prove simultaneous game execution. Missing/modified seed, one failed case, timeout, report absence or modes disagreeing must remain red. Do not combine #3229 and #3238 in one unreviewed experiment.

## Minimal immutable P1 admission contract (to review, not authorize by this page)

For a manual batch of 2–5 *genuinely* compatible ready PRs, freeze the exact base main SHA, member PR numbers/head SHAs, member work IDs, candidate SHA and complete original Git tree objects. An independently reviewed checker must establish all of the following **before** tests may be attributed to that batch:

1. **Source census equality:** recursively enumerate every base and candidate entry, including `path`, Git `type`, `mode` and object SHA; compare the complete base→candidate delta to the exact justified combined member delta. Reject any extra file, unintended removal, type change, mode change or source after-the-fact edit, even when all nominated member file blobs still match.
2. **Member identity and collisions:** distinguish PR/member ID from shared work-board ID; require real ready heads, same-source scope, complete untruncated GitHub pages, no path casing, alias, directory-prefix, rename/copy, generated-output or semantic shared-state conflict. A matching pathname set alone is insufficient.
3. **Race/ownership:** observe base and all heads before and after the read; confirm no active writer or unresolved review/merge conflict. Readback narrows an observation window; it cannot make mutable refs permanently immutable. A changed ref creates a **new candidate**.
4. **Test identity and negative preservation:** fix expected test IDs and scripts before build; bind actual runner checkout/compiled binary/fixture/ZIP hashes and each unmodified test body. Reconcile **all** passed, failed, expected skipped and missing cases, including cancelled/partial jobs. No output, no attribution.
5. **Independent trust and cost:** untrusted PR code may only use the existing approved hosted route, never arbitrary execution on the owner's HP. Preserve conventional required checks until source, full test equivalence, two matched conventional-vs-shared candidate pairs (at most three if contradictory) and distinct technical review establish a benefit. No beta, original/native or physical QA credit flows from this contract.

**Required negative controls:** add an unexpected candidate-only file; preserve a member blob while changing mode `100644` to `100755`; introduce casefold/file-vs-directory alias; delete/rename a source without accounting for the old path; change a PR head mid-census; return a truncated paginated file list; duplicate or omit a case; change script/fixture/EXE/ZIP identity; accept a green partial Windows job while another failed or was cancelled. Every scenario must fail closed. These are explicit acceptance cases for a **future permitted implementation**, not instructions to circumvent the earlier publication block.
