# QA-01: source-tally-anchored original/native Bowl phase capture

**Purpose:** distinguish the one-scene-relative-frame original/native onset gap from a divergence *after the independently observed real stunt tally*. The completed 2014 Bowl run from [green PR #1119](https://github.com/gamesbyian/UR-Recomp/pull/1119) proves that both source-qualified fresh guests report a real scored `0x2F` tally at script host frame **4279**, and both observe the settled result `0x18` at absolute host frame **4349**, 70 frames later. The scene-relative difference arises because original race-entered is at host frame **984**, native at **985**. That alone cannot determine guest CPU/NMI phase causality.

The new `--bowl-tally-phase` flag adds **eight zero-frame read-only dumps at host frames 4333, 4339, 4343, 4344, 4345, 4346, 4347 and 4348**, corresponding to +54/+60/+64/+65/+66/+67/+68/+69 from the guest-observed genuine tally. Both original Snes9x and native Baldosa use the same zero-frame script grammar. The existing original movie scene controller masks, embedded SRAM, fresh stock entries and guest rules remain unchanged. The original/native `0x2F` tally detection still gates the snapshots before they run; the `0x18` result check remains downstream.

The producer now validates every **absolute host dump frame** on both guests, complete 131,072B WRAM + 65,536B VRAM + 512B CGRAM lengths, and counts byte disagreements at each matched tally-relative boundary. The bounded report also includes `7E:009F` menu, `7E:00CE` course, and `7E:0313` in-race values for both engines. It fails closed if the tally/result host interval differs from the demonstrated 70 frames or a dump is missing or malformed. Diagnostic result success remains governed by the independently verified one-frame scene-relative phase-witness predicate and is **not** conditional on byte-for-byte equality.

The resulting evidence discriminates a genuine **post-tally** guest-state change from a discrepancy wholly in **course-entry versus stable-tally anchoring**. Exact full-memory equality at the same host frame still would not establish equality of CPU opcode timing, guest NMI entry or PPU raster phase; it would instead justify a dedicated guest-PC/scanline experiment at the earliest inconsistent field. Likewise, any VRAM palette differences may be presentation phase, not different stunt physics.

No user-facing product component changes. **Official completed USA course acceptance remains 0/45**; the result is a research probe only. The workflow retains the compact report and text logs, not ROM, SRAM or raw guest memory dumps.

The earlier source artifact recorded **counts only**, so the hypothesis that the repeated six WRAM discrepancies concern the same addresses is *not yet proven*.
