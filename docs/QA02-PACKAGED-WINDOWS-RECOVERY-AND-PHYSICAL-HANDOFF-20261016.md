## Player-visible original Windows save-failure acceptance (P0 #1751)

A protected canonical directory is **necessary but not sufficient** if the actual player is falsely told Quit succeeded. Independent QA reproduced two distinct genuine Windows failures against #1713 on separate **exact-bound PR-merge executables**, neither on the old nominated owner ZIP:

- **Prewrite NTFS DACL denial:** [run 38999478028](https://github.com/gamesbyian/UR-Recomp/actions/runs/38999478028), exact original process frame 1952, source guest `save_profile_lock_unavailable` / `native_save_preflight_failed`, all four canonical files unchanged, two cold boots pass, but process **exit 0**. This is a refusal *before raw*.
- **Postraw live typed publication denial:** [run 39002412479](https://github.com/gamesbyian/UR-Recomp/actions/runs/39002412479), actual tested PR-merge `f252a2b48b89614f421cf7a184eb579fd644afb1` and original fault artifact `12090230164` (SHA256 `2de4154e62eb99c47379777e73468a2012802181502c30a64378d176f73b373f`). The same genuine frame-1952 guest wrote 28 changed 8-KiB SRAM bytes, then a second Windows process blocked atomic typed replacement by holding `CreateFileW` **without `FILE_SHARE_DELETE`** on the existing typed file (independently observed WinError 5 on a disposable replacement probe). The original typed CAS emitted **`CHECKPOINT profile=native-ci-rider status=io_error`**, left old typed/selector/catalog and exact pending intent intact, and later cold processes reconciled once. The failed game again reported **exit 0**. The earlier attempt [39001425944](https://github.com/gamesbyian/UR-Recomp/actions/runs/39001425944) to use *directory DACL denial* for this same postraw typed boundary is a **real negative**: it allowed the actual typed CAS to commit. Do not replace these distinctions with a synthetic failure return.

**Acceptance path on a newly integrated, source/PE/ZIP-pinned Windows package, disposable profile only:**

1. Run ordinary clean Quit with unchanged guest SRAM; expect successful game shutdown, no warning, no extra checkpoint, and canonical data stable.
2. Run a source-authentic changed SRAM race followed by actual **prewrite** OS denial. Do not force a stale writer or advise overwriting another live game.
3. Separately run actual **postraw/live typed CAS** sharing-denial using the existing Windows source test hook and native OS handles. Verify the player receives a **distinct or adequately comprehensive unsaved-checkpoint warning** before closure, no success falsehood, and an understandable action for recovery/retry. Cold replay must reconcile once and not double-publish on the second boot.
4. Deliberately force a **stale same-profile game A** while newer game B has committed. A must not overwrite B, and the player must receive an intelligible refused-save notice. Do not automatically retry the stale A write or destroy B's successful checkpoint.
5. Exercise operator **R/T/S/Q** by actual human keystrokes in a no-arguments package launch and preserve console transcript plus the four canonical snapshots for each choice. An automated `choice.exe` source inspection, scripted `UR_BALDOSA_RECOVERY_ACTION` injection or successful saved-byte checksum cannot substitute for this player-operated witness.

Keep original user data out of the uploaded artifact; record only disposable hashes and sanitized logs.
