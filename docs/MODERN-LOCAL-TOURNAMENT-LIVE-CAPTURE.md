# Local Tournament: real 2P capture owner

Status: Windows product-host integration code, with an opt-in native acceptance route. Ordinary stock 2P still supplies the only match result authority. Player-visible fixture selection remains unimplemented.

The existing ordinary-2P production recorder now checks a separately armed coordinator fixture at actual race start. Only the live Modern-confirmed profiles and guest-observed canonical course can attach the pre-race fixture attempt token. The recorder retains that token for its own lifetime. It continues saving the existing .urrun/.urmatch pair through the established transactional producer, then passes the exact saved run path and retained token to the coordinator. A successful coordinator commit writes an instance-scoped receipt link before awarding fixture points. A lost/stale capture cancels only its own attempt; wrong course/profiles can never gain fixture credit. Ordinary Records remain valid even if supplemental tournament membership fails.

On first ordinary 2P race entry, the host can reload a previously created tournament session from the established per-user data root under local-tournaments. An abandoned guest race is not restored. The manual native acceptance opt-in UR_LOCAL_TOURNAMENT_NATIVE_ACCEPTANCE=join.alpha,join.bravo creates and arms a one-fixture test tournament only after TWO independent Modern join-overlay profiles have been confirmed. It uses fixed known fixture IDs in that opt-in acceptance route alone; production caller/UI must mint independent unique IDs. The native fresh-process checker verifies a real stored match's supplemental receipt produced by the host (not reconstructed from roster/course coincidence) and derives the final 3/0 standings from it. This acceptance requires the real-join-to-Records harness from PR #808. No claim of success until that native run actually passes.

Implementation is intentionally scoped to the existing ordinary 2P recorder and native build source registration. It does not write guest SRAM, route a stock menu, modify profile input assignment, invent results, or construct a second multiplayer Records model.


## Read-only Windows product query API

The live host now exports three C-compatible, bounded read-only queries in `uniracers_modern_host.h`: tournament overview (entrant/fixture/completed counts and completion), a canonical indexed fixture (round, two profile storage IDs, ordinary-Race course and authoritative winner/draw oriented back to the scheduled entrants even when race seats swapped), and ranked standings (played, W/L/D and existing 3/1/0 points). They derive directly from the exact active coordinator session and validated receipt-based results. Calls return unavailable in Authentic mode or without a restored/active tournament, and never append run records, create results or mutate SRAM. A C11 header acceptance keeps the ABI usable by existing native frontend code. The visual rendering and normal fixture selector remain under the separate Modern UI ownership lane.

Remaining shipping gap: explicitly start/continue tournaments and select/route fixtures from a Uniracers-native Modern Local Tournament surface, securely generate per-instance/per-attempt IDs for normal users, preserve confirmed profile/source context through stock routing and validate the entire start-to-completed-tournament sequence on a real Windows package. Do not merge native acceptance claims with model-only test results.
