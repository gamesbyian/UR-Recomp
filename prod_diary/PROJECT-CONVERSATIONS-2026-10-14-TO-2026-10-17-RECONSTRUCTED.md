**Source and limitation:** Reconstructed from the Uniracers project conversation summaries and relevant user instructions available in this project, cross-checked against named GitHub PRs. **Not** a verbatim transcript or an exhaustive export of individual agent chats. ## October 14–15: ambitious product direction, original/native fidelity, and outside references

The user wanted the Uniracers remaster to be a modern 4K widescreen, controller-first Windows product that otherwise played exactly like the original. They preferred not to personally playtest unfinished alphas and betas; they found it appealing to direct agents toward a complete product before their own first serious test. This was a quality ambition, not a statement that beta was ready. They asked agents to continue in separate graphics, CPU/APU, Modern and independent QA lanes, recover stalled sessions, and keep the repository defensible. The user's recurring “Please keep going, as far as you can” and “Session stalled. Please recover and resume” were workflow instructions.

The user asked whether new activity in [malmazuke/unirally-reconstruction](https://github.com/malmazuke/unirally-reconstruction) and [morluto/rea](https://github.com/morluto/rea) could help and instructed the assistants to incorporate useful findings into project planning. They expected the repository to accumulate useful reference knowledge, not speculative code substitutions. External PAL gameplay/menu evidence was to be source-qualified against USA before any adoption.

In parallel the Windows owner ZIP was nominated as an immutable source/ZIP pair under [#1667](https://github.com/gamesbyian/UR-Recomp/pull/1667); this was not a gate pass. The agents' implementation and QA sessions are separately documented in their PRs rather than invented here as conversational quotations.

## October 16: agents keep testing; no shortcut through acceptance

The user continued asking the independent QA, graphics, Modern recovery and CPU/APU agents to carry their most difficult source-based work forward. Relevant requests concerned the first complete original/native USA event, reconstituted SPC timing, authentic 1P/2P source-visible pixels, Windows profile/SRAM transactions and process/disk failures. They asked for continued autonomous progress rather than waiting for decisions.

The user requested a repository-hygiene sweep when all agents were idle: check red CI, rescue orphaned work, reconcile PRs and produce fresh assignments. Subsequent integration work culminated in [#1744](https://github.com/gamesbyian/UR-Recomp/pull/1744), reconciling Windows RF-017 source generation with exact-composite cold guest proof. Recorded green journeys and source evidence remained distinct from physically accepted release readiness. The original/core event denominator remained 0/45.

## October 17: four-agent dispatch and follow-on course corrections

When asked for four fresh agent prompts with no Claude model split, the assistant supplied four exclusive roles: (1) original/native USA gameplay and CPU/APU, (2) Modern Windows profile/SRAM recovery, (3) source-authentic SNES raster/4K graphics, and (4) independent Windows release QA/hygiene. The user also asked whether to run research factories overnight. The recommendation was to **skip broad factories**, because bounded RF-034/other discoveries had actionable next causal discriminators, Windows recovery needed actual process and OS faults, and Actions capacity was more valuable for the current owners' real tests.

On follow-up, the user requested an assessment of progress and whether to continue those agents or start over. The assistant checked PRs and Actions, reported genuine integration and research movement, identified red unit/Windows runs without masking their scope, and recommended keeping the same agents because of accumulated context. The user asked that these be rewritten as full continuation prompts. They were supplied with refreshed main/CI preflights and exclusive ownership, the source-identity caveats, research hold boundaries, acceptance gates and required exact-head validation.

The user later reported the repository quiet and requested merging, closing, orphan rescue and documentation refresh. A cleanup pass inspected nine open PRs and a red full-NTFS Modern bridge run; closed explicitly research-only [#1809](https://github.com/gamesbyian/UR-Recomp/pull/1809), retained its branch, annotated [#1713](https://github.com/gamesbyian/UR-Recomp/pull/1713) with the actual setup-phase ENOSPC CI failure, updated the bounded work queue, and preserved the historical orphan census in [#1711](https://github.com/gamesbyian/UR-Recomp/issues/1711). This was a partial conservative cleanup, not a claim that the repository had no blockers or that all 99 historical PR-less refs were reconciled.

Finally the user asked what malmazuke's repo had produced over approximately two days, and whether to incorporate it before moving on. The assistant identified merged upstream [#81 LEAGUE-TOURS](https://github.com/malmazuke/unirally-reconstruction/pull/81) and [#82 PODIUM-AUDIO](https://github.com/malmazuke/unirally-reconstruction/pull/82), with concrete conditional relevance to original controller ownership, league scoring, records, podium exit and sound sequencing. The user asked the assistant to prepare UR-Recomp for the next dispatch as best it could. [#1816](https://github.com/gamesbyian/UR-Recomp/pull/1816) was created to carry exact upstream source identities and PAL/USA limitations into the repository's cross-project reference and next-dispatch queue. The PR was left awaiting exact-head green CI, not claimed merged.
